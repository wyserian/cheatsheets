PowerShell

PowerShell is a cross-platform command-line shell and scripting language from Microsoft, first released in 2006. Unlike traditional shells such as Bash or CMD, which pass plain text between commands, PowerShell passes .NET objects with properties and methods. This makes it a powerful tool for system administration and automation on Windows, Linux, and macOS, and the main management interface for Windows Server, Active Directory, Azure, and Microsoft 365.

Key Features
  • Object-Based Pipeline : Commands output structured objects, so you filter and sort by property (Status, CPU) instead of parsing text with tools like grep and awk.
  • Consistent Verb-Noun Commands : Commands (cmdlets) follow a predictable naming pattern like Get-Process and Stop-Service, so they are easy to discover and guess.
  • Full Scripting Language : Variables, functions, loops, error handling, classes, and modules.
  • .NET Access : Any .NET class can be used directly, e.g. [System.IO.Path]::GetTempPath().
  • Providers : The registry, environment variables, and certificate store can be browsed like drives (HKLM:, Env:, Cert:).
  • Remoting : Run commands on one or many remote machines over WinRM or SSH.

Getting Help

PowerShell is designed to be self-documenting. Three commands let you discover almost anything: Get-Command finds commands, Get-Help explains them, and Get-Member shows what an object contains.

Get-Command *service* # find commands by name Get-Command -Verb Get -Noun *Net* # find by verb and noun Get-Help Get-Process # short help for a command Get-Help Get-Process -Examples # usage examples only Get-Help Get-Process -Online # open full docs in the browser Update-Help # download the latest help files Get-Process | Get-Member # list an object's properties and methods Get-Alias ls # what command is 'ls' an alias for? Get-Alias -Definition Get-ChildItem # all aliases of a command Get-History # commands run in this session
  • Tab Completion : Press Tab to complete command names, parameters, paths, and even property names.
  • PSReadLine : Built-in line editor with history search (Ctrl + R) and predictive suggestions from your history.

Cmdlets & Syntax

A cmdlet (pronounced "command-let") is a lightweight built-in command named in Verb-Noun form. The verb says what action is performed and the noun says what it acts on. Commands are case-insensitive.

Verb-Noun -ParameterName Value -SwitchParameter Get-ChildItem -Path C:\Logs -Filter *.log -Recurse
Common Approved Verbs
  • Get / Set : Read or change something (Get-Date, Set-Location).
  • New / Remove : Create or delete (New-Item, Remove-Item).
  • Start / Stop / Restart : Control processes and services (Start-Service).
  • Add / Clear : Append to or empty something (Add-Content, Clear-Host).
  • Import / Export / ConvertTo / ConvertFrom : Move data in and out of formats (Export-Csv, ConvertTo-Json).
  • Invoke / Test : Run something or check a condition (Invoke-Command, Test-Path).

Run Get-Verb to see the full list of approved verbs.

Types of Parameters
  • Named : Passed by name, in any order: Get-Process -Name chrome.
  • Positional : The name can be omitted for some parameters: Get-Process chrome.
  • Switch : A flag with no value, on when present: -Recurse, -Force.
  • Abbreviated : Parameter names can be shortened while still unique: -Rec for -Recurse (avoid in scripts).
Common Parameters (Work on Most Cmdlets)
  • -WhatIf : Shows what would happen without doing it. Use before any destructive command.
  • -Confirm : Asks for confirmation before each change.
  • -Verbose / -Debug : Show extra detail about what the command is doing.
  • -ErrorAction : Controls what happens on an error (Stop, Continue, SilentlyContinue).
  • -OutVariable : Saves the output to a variable while still passing it on.
Remove-Item C:\Temp\*.tmp -WhatIf # What if: Performing the operation "Remove File" on target "C:\Temp\a.tmp".
Syntax Rules
  • Comments : # single line and <# multi-line #>.
  • Line Continuation : Lines can break after a pipe |, comma, or opening bracket. A backtick ` also continues a line but is fragile; prefer splatting (see Functions).
  • Escape Character : The backtick: `n (newline), `t (tab), `" (quote).
  • Multiple Statements : Separate with a semicolon: cd C:\; ls.
  • Call Operator & : Runs a command stored in a string or a path with spaces: & "C:\Program Files\App\app.exe" --help.

Pipeline & Objects

The pipeline | sends the output of one command as input to the next. Because objects flow through it, not text, every command downstream can work with named properties directly. Inside script blocks, $_ (or $PSItem) refers to the current object.

# Top 5 processes by CPU time, showing only name, ID, and CPU Get-Process | Sort-Object CPU -Descending | Select-Object -First 5 Name, Id, CPU # Running services whose name starts with "Win" Get-Service | Where-Object { $_.Status -eq 'Running' -and $_.Name -like 'Win*' }
Core Pipeline Cmdlets
  • Where-Object (where, ?) : Filters objects. Simplified form: Where-Object Status -eq 'Running'.
  • Select-Object (select) : Picks properties or items: -First, -Last, -Unique, -ExpandProperty.
  • Sort-Object (sort) : Sorts by one or more properties: Sort-Object Length -Descending.
  • ForEach-Object (foreach, %) : Runs a script block for each object: ForEach-Object { $_.Name.ToUpper() }.
  • Group-Object (group) : Groups objects by a property and counts them.
  • Measure-Object (measure) : Count, sum, average, min, max: Measure-Object Length -Sum -Average.
  • Tee-Object (tee) : Saves output to a file or variable and passes it on.
Formatting & Output
  • Format-Table (ft) / Format-List (fl) : Display as a table or a property list. Format-List * shows every property.
  • Out-File / Out-GridView : Write to a file, or show an interactive filterable window (Windows).
  • Export-Csv / Import-Csv : Save and load objects as CSV.
  • ConvertTo-Json / ConvertFrom-Json : Convert objects to and from JSON.
Always use Format-* cmdlets last in a pipeline. They turn objects into display formatting, so nothing useful can follow them.
Calculated Properties
# 10 largest files with their size in MB Get-ChildItem -Recurse -File | Sort-Object Length -Descending | Select-Object -First 10 Name, @{ Name = 'SizeMB'; Expression = { [math]::Round($_.Length / 1MB, 2) } }

Variables & Data Types

Variables start with $, are case-insensitive, and do not need to be declared. Their type is inferred, but you can enforce one with a type cast.

$name = "Rahul" $count = 42 [int]$port = "8080" # type constraint: the string is converted to an int $port = "abc" # error: cannot convert "abc" to int $a, $b = 1, 2 # multiple assignment $a, $b = $b, $a # swap Remove-Variable name # delete a variable
Common Types
  • Primitives : [string], [int], [long], [double], [decimal], [bool], [char].
  • Others : [datetime], [array], [hashtable], [xml], [regex], [pscustomobject].
  • Type Check : $x.GetType().Name or $x -is [int].
  • Size Suffixes : 1KB, 1MB, 1GB are numeric literals (1MB = 1048576).
Strings
$name = "World" "Hello $name" # double quotes expand variables: Hello World 'Hello $name' # single quotes are literal: Hello $name "Total: $(2 + 3)" # subexpression $( ): Total: 5 "{0} has {1} items" -f "Cart", 3 # format operator $text = @" Multi-line here-string. Variables like $name still expand. "@ # closing "@ must start the line "PowerShell".Length # 10 "PowerShell".ToUpper() # POWERSHELL "a,b,c" -split "," # array: a b c @("a","b","c") -join "-" # a-b-c "Hello World".Replace("World", "PS")
Arrays
$nums = @(10, 20, 30) $nums = 1..5 # range: 1 2 3 4 5 $nums[0] # first element $nums[-1] # last element $nums[1..3] # slice $nums.Count # length $nums += 6 # append (creates a new array) $list = [System.Collections.Generic.List[int]]::new() $list.Add(7) # efficient growable list for large loops
Hashtables
$user = @{ Name = "Rahul"; Role = "Admin"; Age = 30 } $user.Name # Rahul $user["Role"] # Admin $user.City = "Pune" # add a key $user.Remove("Age") $user.Keys; $user.Values $user.ContainsKey("Name") # True $ordered = [ordered]@{ First = 1; Second = 2 } # keeps insertion order
Custom Objects
$server = [PSCustomObject]@{ Name = "web01" IP = "10.0.0.5" Online = $true } $server.Name $server | Export-Csv servers.csv -NoTypeInformation
Automatic Variables
  • $_ / $PSItem : The current object in the pipeline.
  • $true, $false, $null : Boolean and null values.
  • $? : True if the last command succeeded.
  • $LASTEXITCODE : Exit code of the last native program (e.g. git, ping).
  • $Error : List of recent errors; $Error[0] is the latest.
  • $args : Arguments passed to a script or function without declared parameters.
  • $PSScriptRoot : Folder of the running script, useful for relative paths.
  • $HOME, $PWD, $PID : Home folder, current location, current process ID.
  • $env:NAME : Environment variables, e.g. $env:PATH, $env:USERNAME. Set with $env:API_URL = "https://..." (current session only).

Operators

PowerShell uses word-style operators that start with a dash. Symbols like > and < are reserved for redirection, so 5 > 3 creates a file named 3; use 5 -gt 3 instead.

Comparison Operators
Operator Meaning Example (Result)
-eq / -ne Equal / not equal 5 -eq 5 (True)
-gt / -ge Greater than / or equal 10 -gt 3 (True)
-lt / -le Less than / or equal 2 -le 2 (True)
-like / -notlike Wildcard match (*, ?) "report.pdf" -like "*.pdf" (True)
-match / -notmatch Regex match (fills $Matches) "v7.4" -match "\d+\.\d+" (True)
-contains / -notcontains Collection contains value @(1,2,3) -contains 2 (True)
-in / -notin Value is in collection 2 -in @(1,2,3) (True)
-replace Regex replace "a-b" -replace "-", "_" (a_b)
-is / -as Type check / type conversion "5" -as [int] (5)

String comparisons are case-insensitive by default. Prefix with c for case-sensitive (-ceq, -clike, -cmatch).

Other Operators
  • Arithmetic : + - * / %. + also joins strings and arrays.
  • Assignment : = += -= *= /= %= ++ --.
  • Logical : -and, -or, -xor, -not (or !).
  • Split & Join : "a b c" -split " ", $arr -join ",".
  • Range : 1..10.
  • Ternary (PS 7+) : $status = $age -ge 18 ? "Adult" : "Minor".
  • Null-Coalescing (PS 7+) : $name ?? "Guest" uses the right side if the left is $null; $x ??= 10 assigns only if null.
  • Pipeline Chain (PS 7+) : cmd1 && cmd2 runs cmd2 only if cmd1 succeeded; cmd1 || cmd2 only if it failed.
Redirection
Get-Process > procs.txt # write output to a file (overwrite) Get-Process >> procs.txt # append cmd 2> errors.txt # redirect errors only cmd 2>&1 # merge errors into normal output cmd *> all.txt # redirect all streams cmd > $null # discard output

Control Flow

If / ElseIf / Else
$disk = Get-PSDrive C $freeGB = $disk.Free / 1GB if ($freeGB -lt 10) { Write-Warning "Low disk space: $([math]::Round($freeGB)) GB" } elseif ($freeGB -lt 50) { Write-Host "Disk space OK" } else { Write-Host "Plenty of space" }
Switch
switch ((Get-Date).DayOfWeek) { "Saturday" { "Weekend" } "Sunday" { "Weekend" } default { "Weekday" } } switch -Wildcard ($file) { # also -Regex, -CaseSensitive "*.log" { "Log file" } "*.csv" { "Data file" } }
Loops
foreach ($svc in Get-Service) { # foreach statement if ($svc.Status -eq 'Stopped') { continue } $svc.Name } for ($i = 0; $i -lt 5; $i++) { "Count $i" } $retries = 0 while ($retries -lt 3) { $retries++ } do { $answer = Read-Host "Continue? (y/n)" } until ($answer -in 'y', 'n') 1..10 | ForEach-Object { $_ * 2 } # pipeline version # PS 7+: run iterations in parallel threads $servers | ForEach-Object -Parallel { Test-Connection $_ -Count 1 } -ThrottleLimit 5
  • break / continue : Exit the loop, or skip to the next iteration.
  • foreach vs ForEach-Object : The foreach statement loads the whole collection first and is faster; ForEach-Object streams items one at a time through the pipeline and uses less memory for large data.

Functions, Scripts & Modules

Functions
function Get-Greeting { param( [string]$Name = "World" ) "Hello, $Name!" } Get-Greeting # Hello, World! Get-Greeting -Name "Rahul" # Hello, Rahul!
A function returns everything it outputs, not just the value after return. Any uncaptured expression ends up in the result. Discard unwanted output with $null = ... or | Out-Null.
Advanced Functions

Adding [CmdletBinding()] makes a function behave like a real cmdlet: it gains common parameters (-Verbose, -ErrorAction), and with SupportsShouldProcess it supports -WhatIf and -Confirm.

function Remove-OldLogs { [CmdletBinding(SupportsShouldProcess)] param( [Parameter(Mandatory)] [ValidateScript({ Test-Path $_ })] [string]$Path, [ValidateRange(1, 365)] [int]$Days = 30 ) $cutoff = (Get-Date).AddDays(-$Days) Get-ChildItem $Path -Filter *.log | Where-Object LastWriteTime -lt $cutoff | ForEach-Object { if ($PSCmdlet.ShouldProcess($_.Name, "Delete")) { Remove-Item $_.FullName Write-Verbose "Deleted $($_.Name)" } } } Remove-OldLogs -Path C:\Logs -Days 7 -WhatIf -Verbose
Parameter Attributes
  • [Parameter(Mandatory)] : PowerShell prompts for the value if it is not given.
  • [Parameter(ValueFromPipeline)] : Accepts input from the pipeline (process it in a process { } block).
  • [ValidateSet("A","B")] : Only allows listed values and enables tab completion for them.
  • [ValidateRange(1,10)], [ValidatePattern("regex")], [ValidateNotNullOrEmpty()] : Built-in input validation.
  • [switch] : A true/false flag parameter, like -Force.
Splatting

Pass parameters as a hashtable with @ instead of $. Cleaner than long lines or backticks.

$params = @{ Path = "C:\Reports" Filter = "*.pdf" Recurse = $true ErrorAction = "SilentlyContinue" } Get-ChildItem @params
Scripts

A script is a .ps1 file. It can declare a param() block at the top, just like a function.

.\deploy.ps1 -Environment Prod # run a script in the current folder (.\ required) . .\helpers.ps1 # dot-source: load its functions/variables into this session & "C:\My Scripts\run.ps1" # call operator for paths with spaces pwsh -File .\script.ps1 # run in a new PowerShell process pwsh -Command "Get-Date" # run a one-off command
Modules

Modules package reusable cmdlets and functions. They are installed from the PowerShell Gallery and auto-load when one of their commands is first used.

Find-Module *Azure* # search the PowerShell Gallery Install-Module Az -Scope CurrentUser # install without admin rights Import-Module Az # load explicitly Get-Module -ListAvailable # installed modules Update-Module Az Get-Command -Module Microsoft.PowerShell.Management
Profile

The profile is a script that runs every time PowerShell starts, used for aliases, functions, and prompt customization. Its path is stored in $PROFILE.

if (!(Test-Path $PROFILE)) { New-Item $PROFILE -Force } notepad $PROFILE # or: code $PROFILE . $PROFILE # reload after editing

Reading & Writing Files

Providers & Drives

PowerShell exposes other data stores as drives, so the same cmdlets (Get-ChildItem, Get-Item, Set-Item) work on them.

  • FileSystem : C:, D:, or / on Linux.
  • Env : Environment variables: Get-ChildItem Env:.
  • Registry (Windows) : HKLM: and HKCU:, e.g. Get-ItemProperty HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion.
  • Cert (Windows) : Certificate store: Get-ChildItem Cert:\CurrentUser\My.
  • Variable / Function / Alias : Everything defined in the session.

Processes

Services (Windows)
Get-Service # all services Get-Service | Where-Object Status -eq Running Get-Service wuauserv | Select-Object * # all properties of one service Start-Service Spooler Stop-Service Spooler Restart-Service Spooler Set-Service Spooler -StartupType Disabled
System Information
Get-ComputerInfo # OS, hardware, BIOS (Windows) Get-CimInstance Win32_OperatingSystem # OS details via CIM/WMI Get-CimInstance Win32_LogicalDisk | Select-Object DeviceID, @{n='FreeGB';e={[math]::Round($_.FreeSpace/1GB)}} Get-PSDrive -PSProvider FileSystem # drives and free space (cross-platform) Get-HotFix # installed Windows updates Get-LocalUser # local user accounts Get-WinEvent -LogName System -MaxEvents 20 # recent event log entries Get-Date -Format "yyyy-MM-dd HH:mm" # formatted date Restart-Computer -WhatIf

Networking & Web

Network Diagnostics
Test-Connection google.com -Count 2 # ping Test-NetConnection google.com -Port 443 # is a TCP port reachable? (Windows) Resolve-DnsName example.com -Type MX # DNS lookup (Windows) Get-NetIPAddress -AddressFamily IPv4 # IP addresses (Windows) Get-NetTCPConnection -State Listen # listening ports (Windows) Get-NetAdapter # network adapters (Windows)
Web Requests & REST APIs
  • Invoke-WebRequest (iwr) : Returns the full HTTP response: status code, headers, raw content. Use it to download files or inspect responses.
  • Invoke-RestMethod (irm) : Returns just the body, and automatically converts JSON or XML into PowerShell objects. Best for APIs.
# GET: JSON is converted to objects automatically $repo = Invoke-RestMethod https://api.github.com/repos/PowerShell/PowerShell $repo.stargazers_count # POST JSON with a header $body = @{ title = "Bug report"; priority = 2 } | ConvertTo-Json Invoke-RestMethod -Uri https://api.example.com/issues -Method Post ` -Body $body -ContentType "application/json" ` -Headers @{ Authorization = "Bearer $env:API_TOKEN" } # Download a file and check the status code Invoke-WebRequest https://example.com/file.zip -OutFile file.zip (Invoke-WebRequest https://example.com).StatusCode # 200

Error Handling & Streams

Types of Errors
  • Non-Terminating : The cmdlet reports the error and keeps going, e.g. Get-Item on several paths where one is missing. Most cmdlet errors are this type, and try/catch does not catch them by default.
  • Terminating : Stops execution. Produced by throw, syntax errors, .NET exceptions, or any error when -ErrorAction Stop is used.
Try / Catch / Finally
try { $content = Get-Content C:\missing.txt -ErrorAction Stop # make it terminating } catch [System.Management.Automation.ItemNotFoundException] { Write-Warning "File not found" } catch { Write-Error "Unexpected error: $($_.Exception.Message)" } finally { Write-Verbose "Always runs, for cleanup" } throw "Config file is invalid" # raise your own terminating error $ErrorActionPreference = 'Stop' # make every error terminating in this script
Output Streams

PowerShell has six output streams, so data and messages never get mixed up. Only the success stream flows into the next command in a pipeline.

# Stream Write With Shown By Default
1 Success (output) Write-Output or just the value Yes
2 Error Write-Error Yes
3 Warning Write-Warning Yes
4 Verbose Write-Verbose No (use -Verbose)
5 Debug Write-Debug No (use -Debug)
6 Information Write-Information, Write-Host Write-Host only

Write-Output vs Write-Host : Write-Output sends data down the pipeline (it can be captured and processed). Write-Host only displays text on screen, so use it for messages, not results.

Remoting & Jobs

Remoting

PowerShell Remoting runs commands on remote machines. Windows uses WinRM (ports 5985 HTTP / 5986 HTTPS); PowerShell 7 can also use SSH, which works across Windows, Linux, and macOS.

Enable-PSRemoting -Force # enable WinRM on the target (admin) Enter-PSSession -ComputerName Server01 # interactive remote shell (like SSH) Exit-PSSession Invoke-Command -ComputerName Web01, Web02 -ScriptBlock { Get-Service W3SVC # runs on both servers in parallel } $s = New-PSSession -ComputerName Server01 # reusable persistent session Invoke-Command -Session $s -ScriptBlock { $env:COMPUTERNAME } Copy-Item .\app.zip -Destination C:\Deploy -ToSession $s Remove-PSSession $s Enter-PSSession -HostName user@linux01 # PS 7+: remoting over SSH
Background Jobs

Jobs run commands in the background so the console stays usable.

$job = Start-Job { Get-ChildItem C:\ -Recurse -File | Measure-Object } Get-Job # list jobs and their state Receive-Job $job -Wait # wait and collect the output Remove-Job $job Start-ThreadJob { Invoke-RestMethod https://api.example.com } # lighter, thread-based (PS 7+) Invoke-Command -ComputerName Server01 -ScriptBlock { ... } -AsJob

Execution Policy & Security

The execution policy controls whether PowerShell runs scripts and whether they must be signed. It is a safety feature to prevent accidental script runs, not a security boundary: a user can bypass it, so it does not stop a determined attacker.

Types of Execution Policies
  • Restricted : No scripts can run; interactive commands only. Default on Windows client editions.
  • AllSigned : Only scripts signed by a trusted publisher can run.
  • RemoteSigned : Local scripts run freely; scripts downloaded from the internet must be signed. Default on Windows Server and the most common choice for developers.
  • Unrestricted : All scripts run; warns before running downloaded ones. Default on Linux and macOS, where policies are not enforced.
  • Bypass : Nothing is blocked and there are no warnings. Used by automation tools.
Get-ExecutionPolicy -List # policy at every scope Set-ExecutionPolicy RemoteSigned -Scope CurrentUser # no admin needed Unblock-File .\downloaded-script.ps1 # remove the "downloaded from internet" mark pwsh -ExecutionPolicy Bypass -File .\script.ps1 # one-off override for a single run
Credentials & Secrets
$cred = Get-Credential # secure prompt, returns a PSCredential Invoke-Command -ComputerName Server01 -Credential $cred -ScriptBlock { whoami } $pass = Read-Host "Password" -AsSecureString # masked input # Store secrets in a vault instead of in scripts Install-Module Microsoft.PowerShell.SecretManagement, Microsoft.PowerShell.SecretStore Register-SecretVault -Name Local -ModuleName Microsoft.PowerShell.SecretStore Set-Secret -Name ApiKey -Secret "abc123" $key = Get-Secret -Name ApiKey -AsPlainText
Security Best Practices
  • Never Hard-Code Secrets : Use Get-Credential, SecretManagement, or environment variables.
  • Use -WhatIf First : Preview any bulk delete or change before running it for real.
  • Run with Least Privilege : Only elevate (Run as Administrator) when a task requires it.
  • Review Before Running : Read scripts from the internet before executing them, especially irm ... | iex one-liners, which download and run code immediately.
  • Enable Logging : Script block logging and transcription (Start-Transcript) record what ran, which is essential for security auditing.

Bash vs PowerShell

mv Move-Item mv, move
rm -rf Remove-Item -Recurse -Force rm, del

touch file New-Item file ni

echo Write-Output echo, write

Example: Same Task, Different Approach
# Bash: parse text columns to find the 3 largest files ls -l | sort -k5 -n -r | head -3 | awk '{print $9, $5}' # PowerShell: work with properties directly Get-ChildItem -File | Sort-Object Length -Descending | Select-Object -First 3 Name, Length
