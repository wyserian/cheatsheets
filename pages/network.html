Network

A network is a system of interconnected devices (such as computers, servers, routers, and other hardware) that communicate and share resources using established protocols over wired or wireless connections.

Types of Networks
  • Local Area Network : Covers a small area like an office or home.
  • Wide Area Network : Spans large geographical areas, like the internet.
  • Metropolitan Area Network : Connects multiple LANs within a city or large campus.
  • Personal Area Network : Small-scale network for personal devices like smartphones and laptops.
  • Wireless LAN (WLAN) : A LAN where devices connect over Wi-Fi instead of cables.
Network Segment

A network segment is a subdivision of a computer network where all devices share the same communication medium and can directly communicate without passing through a router or other layer-3 device. It is typically bounded by networking equipment such as switches, routers, or firewalls, and includes a group of computers or devices connected through a shared medium like an Ethernet switch or Wi-Fi access point. Network segmentation helps organize and control traffic within a network, improving performance and enhancing security.

Subnet

A subnet (short for subnetwork) is a logically defined smaller network within a larger IP network, created to organize, manage, and secure network traffic more efficiently. It consists of a range of IP addresses grouped together using a subnet mask, allowing devices within the subnet to communicate directly without routing traffic externally. While a network segment typically refers to a physical grouping of devices on the same medium (like an Ethernet switch), a subnet represents a logical grouping that may span one or more network segments, all configured to use the same router for communication beyond the subnet.

Internet

The internet is a global public network of interconnected computers and devices that use standardized communication protocols to exchange data and information. For effective communication and organization on a network, devices need to have clear identification and be recognizable by others, which typically occurs through unique identifiers assigned to each device, such as IP addresses or MAC addresses. These identifiers enable devices to send and receive data, facilitating communication and maintaining order within the network.

Intranet

An intranet is a private network used within an organization to facilitate communication, share information, and enable collaboration among employees. It operates like the internet but is confined to a specific group or organization, and access is restricted to authorized users only. Key features of an intranet include internal communication, file sharing and storage, collaboration, security, and centralized resources.

Extranet

An extranet is a private network that allows controlled access to external users, typically business partners, vendors, or customers, while maintaining a level of security. It extends a company's internal network (intranet) to authorized users outside the organization. Through an extranet, businesses can securely share information and collaborate with external parties while keeping the main network protected from unauthorized access. It typically involves the use of secure connections, such as virtual private networks (VPNs), to ensure the safety of the data being exchanged.

VLAN (Virtual LAN)

A VLAN splits one physical switch (or a set of switches) into multiple isolated logical networks. Devices in different VLANs cannot talk to each other directly, even when plugged into the same switch, unless traffic passes through a router or Layer 3 switch. Frames are tagged with a VLAN ID using the IEEE 802.1Q standard. Example: employees on VLAN 10, guests on VLAN 20, and IP cameras on VLAN 30, all sharing the same switches.

  • 802.1Q Tag : a 4-byte field inserted into the Ethernet frame, carrying a 12-bit VLAN ID (1 to 4094 usable).
  • Access Port : belongs to one VLAN and carries untagged frames, for end devices like PCs and printers.
  • Trunk Port : carries tagged frames for many VLANs between switches, routers, and hypervisors; the native VLAN travels untagged.
  • Inter-VLAN Routing : traffic between VLANs must pass through a router or Layer 3 switch, where it can be filtered by ACLs or a firewall.
Network Topologies

A topology is the arrangement in which nodes are connected in a network.

  • Bus : All devices share a single backbone cable. Cheap and simple, but one cable fault brings down the whole network.
  • Star : All devices connect to a central switch. Easy to manage and the most common LAN topology today, but the central device is a single point of failure.
  • Ring : Each device connects to two neighbors, forming a closed loop that data travels around. A single break disrupts the network unless a dual ring is used.
  • Mesh : Devices connect to many (partial mesh) or all (full mesh) other devices. Highly redundant and fault-tolerant, but expensive. Used in WAN backbones and mesh Wi-Fi.
  • Tree (Hierarchical) : Star networks linked together in a hierarchy. Common in enterprise and campus networks.
  • Hybrid : A combination of two or more topologies.
Network Architectures
  • Client-Server : Clients request services from central servers (web, email, databases). Easier to secure and manage centrally.
  • Peer-to-Peer (P2P) : Every node acts as both client and server and shares resources directly with others. Example: BitTorrent.
Performance Terms
  • Bandwidth : The maximum amount of data a link can carry per second, e.g. a 100 Mbps connection.
  • Throughput : The amount of data actually transferred per second, always less than or equal to the bandwidth.
  • Latency : The time data takes to travel from source to destination, usually measured as round-trip time (RTT) in milliseconds.
  • Jitter : Variation in latency between packets. High jitter causes choppy voice and video calls.
  • Packet Loss : The percentage of packets that never reach their destination, causing retransmissions (TCP) or glitches (UDP).

Networking Nodes

A node in a network is a point where data can be received, sent, created, or stored. It needs identification like an IP address for access and can be any device that processes and shares information with other nodes.

  • Repeater
    • The repeater regenerates the signal over the same network as the signal becomes weak or corrupted when sent over a long distance.
    • Layer 1 device - Physical layer
    • Has no memory
    • Half duplex mode
    • Two port (input and output)
  • Hub
    • Hubs are essentially multi-port repeaters used to setup LANs.
    • Layer 1 device - Physical layer
    • Has no memory
    • Half duplex mode
    • Has multiple ports
    • Supports only broadcasting, thus flooding the network.
  • Bridge
    • Repeater + Functionality of Reading MAC Address, Used for Interconnecting Two LANs on the Same Protocol.
    • Layer 2 device - Data link layer
    • Has memory - stores MAC address table
    • Full duplex mode
    • Multi-port device
    • Supports unicasting, multicasting and broadcasting.
    • Uses MAC address to communicate.
  • Switch
    • Used to connect devices together on a network to establish a LAN (switching is deciding the best route for data transmission).
    • Layer 2 device - Data link layer
    • Has memory - stores MAC address table
    • Full duplex mode
    • Multi-port device
    • Supports unicasting, multicasting and broadcasting.
    • Uses MAC address to communicate.
  • Router
    • Use to connect two or more different LANs using different protocols (forwarding data packets between computer networks).
    • Layer 3 device - Network layer
    • Has memory - stores routing table
    • Full duplex mode
    • Multi-port device
    • Supports unicasting, multicasting and broadcasting.
    • Uses IP address to communicate.
  • Modem
    • Modulator-demodulator: converts digital data into signals suited to the ISP's line (DSL, cable, fiber, cellular) and back again.
    • Layer 1 device - Physical layer
    • Connects a home or office network to the ISP; often combined with a router in a single box.
  • Wireless Access Point (WAP)
    • Lets Wi-Fi devices join a wired network, bridging wireless and Ethernet traffic.
    • Layer 2 device - Data link layer
    • Broadcasts an SSID (network name) and secures connections with WPA2 / WPA3.
Switching & Routing Internals
  • Collision Domain : devices that can collide when sending at once. A hub is one collision domain; every switch port is its own, and full duplex removes collisions entirely.
  • Broadcast Domain : devices that receive each other's broadcasts. A switch forwards broadcasts to all ports (one broadcast domain per VLAN); a router separates broadcast domains.
  • MAC Learning : a switch records the source MAC of every frame and the port it arrived on in its MAC (CAM) table. Frames to a known MAC go out one port; unknown unicast and broadcast frames are flooded to all ports. Entries age out (commonly after 300 seconds).
  • Spanning Tree (STP, IEEE 802.1D / RSTP 802.1w) : disables redundant switch links to prevent loops, which would otherwise cause broadcast storms.
  • Longest Prefix Match : a router picks the most specific route that matches the destination; the default route 0.0.0.0/0 is used only when nothing else matches.

Gateway

A gateway is a network node that acts as an entry and exit point between two different networks, especially networks that use different protocols or architectures. While a router forwards packets between similar networks, a gateway can also translate between different protocols, data formats, or addressing schemes so that the two sides can communicate. A gateway can be a dedicated hardware device, a router with gateway features, or software running on a server.

  • A gateway operates at any layer of the OSI model depending on its purpose, but protocol-translating gateways typically work at the higher layers.
  • In a home network, the router provided by the ISP acts as the gateway between the local network and the internet.
  • The gateway address is configured on every device on the network, usually assigned automatically through DHCP.
Types of Gateways
  • Default Gateway : The node a device sends traffic to when the destination is outside its own subnet. It is usually the local router's IP address, such as 192.168.1.1. If a device cannot reach the internet but can reach local devices, a wrong default gateway is a common cause.
  • Network / Protocol Gateway : Connects networks that use different protocols by translating between them, for example connecting a legacy industrial network to a modern IP network.
  • NAT Gateway : Performs Network Address Translation so that devices with private IP addresses can share one public IP address to access the internet. Cloud providers offer this as a managed service, such as an AWS NAT Gateway that lets instances in a private subnet reach the internet without being reachable from it.
  • API Gateway : An application-level gateway that sits in front of backend APIs and acts as a single entry point for clients. It handles routing to the right service, authentication, rate limiting, and response caching. Examples: AWS API Gateway, Kong, NGINX used as an API gateway in front of microservices.
  • VoIP / Media Gateway : Converts voice traffic between the traditional telephone network (PSTN) and an IP network.
NAT in Detail
  • SNAT / Masquerade : rewrites the source address of outbound packets to the router's public IP.
  • DNAT / Port Forwarding : rewrites the destination of inbound packets, e.g. public port 443 to an internal web server.
  • PAT (NAT Overload) : many private hosts share one public IP; the router tells them apart by assigning each connection a unique public source port and tracking it in a NAT table.
  • CGNAT : ISPs add another NAT layer using 100.64.0.0/10 (RFC 6598), so customers no longer get their own public IPv4 address.
  • NAT Traversal : peer-to-peer apps (WebRTC, VoIP) use STUN to learn their public address and TURN to relay traffic when a direct path is impossible.

MAC Address

A MAC (Media Access Control) address is a unique identifier assigned to a network interface controller (NIC) for communication at the data link layer of a network segment.

  • It is called a physical address.
  • It serves as a hardware address that distinguishes one device from another on a local network or physical hardware.
  • A MAC address is 48 bits long, written as 12 hexadecimal digits in six pairs separated by colons or hyphens (e.g., 00:1A:2B:3C:4D:5E). The first half is the OUI (Organizationally Unique Identifier) that identifies the manufacturer, and the second half is unique to the device.
  • FF:FF:FF:FF:FF:FF is the broadcast MAC address, received by every device on the local network.
  • MAC addresses can be faked or spoofed in a process known as spoofing. This spoofing occurs when a networked device pretends to identify another using its MAC address.
  • The Network Interface Card (NIC) Card’s manufacturer provides the MAC address.
Address Resolution Protocol (ARP)

Address Resolution Protocol (ARP) is a protocol used to map IP addresses to MAC addresses on a local network. This is necessary because while IP addresses are used for routing packets across networks, MAC addresses are needed to deliver the packets to the correct device within a local network.

Request (broadcast) : Who has 192.168.1.1? Tell 192.168.1.20 Reply (unicast) : 192.168.1.1 is at 00:1A:2B:3C:4D:5E

ARP has no authentication, so an attacker on the same network can send fake replies (ARP spoofing) to redirect traffic through their machine.

Address Bits
  • I/G Bit : the lowest bit of the first byte; 0 = unicast, 1 = multicast (all-ones is broadcast).
  • U/L Bit : the second-lowest bit; 0 = globally unique (manufacturer OUI), 1 = locally administered. Phones and modern OSes use random, locally administered MACs per network for privacy.
Ethernet Frame (IEEE 802.3)

ARP in Detail
  • Request (opcode 1) : broadcast asking who owns an IP. Reply (opcode 2) : unicast answer with the MAC.
  • ARP Cache : answers are cached for a short time (view with ip neigh or arp -a).
  • Gratuitous ARP : a host announces its own IP-to-MAC mapping unprompted, used for failover and duplicate-IP detection.
  • No Authentication : any host can send fake replies (ARP spoofing). Switches defend with Dynamic ARP Inspection (DAI) and DHCP snooping.
  • IPv6 : replaces ARP with the Neighbor Discovery Protocol (NDP, RFC 4861), using ICMPv6 Neighbor Solicitation and Advertisement messages.

IP Address

An Internet Protocol (IP) address is a unique numerical label assigned to each device connected to a computer network that uses the Internet Protocol for communication.

  • It is called a logical address.
  • It serves two main purposes: identifying the host or network interface and providing the location of the device in the network.
  • It is calculated through a technique known as IP addressing & subnetting.
  • A device's IP address can be changed, but two devices cannot have the same IP address within the same network.
  • The Internet Assigned Numbers Authority (IANA) manages the global pool of unique IP addresses and delegates them to Regional Internet Registries (RIRs), which distribute them to organizations in their regions. Internet Service Providers (ISPs) obtain IP addresses from RIRs and assign them to customers like businesses and home users.
Type of IP Address
  • IPv4 : Internet Protocol Version 4 (IPv4) is a 32-bit address and written as four decimal numbers separated by dots. The first octet of 127 is reserved for a computer's loopback address. Usually, the address 127.0.0.1 is used. The loopback address provides mechanisms for self-diagnosis and troubleshooting at the machine level. (e.g., 192.168.1.1)
  • IPv6 : Internet Protocol Version 6 (IPv6) is a 128-bit address and written as eight groups of hexadecimal numbers (of 4 digits) separated by colons. ::1 is the local loopback address in IPv6. (e.g., 2001:0db8:85a3:0000:0000:8a2e:0370:7334). It can be shortened by dropping leading zeros and replacing one run of all-zero groups with ::, giving 2001:db8:85a3::8a2e:370:7334.
Categories of IP Address
  • Public : A public address is used to identify the device on the Internet. It is globally unique and assigned by the ISP.
  • Private : A private address is used to identify a device amongst other devices on a local network. Private ranges are not routable on the internet and are reused by every home and office network; devices reach the internet through NAT (Network Address Translation), which maps private addresses to the router's public IP.
  • Static : Manually configured and never changes. Used for servers, printers, and routers.
  • Dynamic : Assigned automatically by a DHCP server for a lease period. Used for laptops and phones.

  • 0.0.0.0 : "Any address". A server bound to 0.0.0.0 listens on all interfaces; 0.0.0.0/0 is the default route.
  • 255.255.255.255 : Broadcast to every host on the local network.
  • 169.254.0.0/16 : Link-local (APIPA). A device assigns itself one of these when it cannot reach a DHCP server, which usually signals a DHCP problem.

Subnetting & CIDR

A subnet mask splits an IP address into a network part and a host part. CIDR (Classless Inter-Domain Routing) notation writes the mask as the number of network bits after a slash. Usable hosts per subnet = 2(32 - prefix) - 2, because the first address (network) and last address (broadcast) cannot be assigned to hosts.

IP Address : 192.168.1.130/26 Subnet Mask : 255.255.255.192 (26 network bits, 6 host bits) Network Address : 192.168.1.128 Broadcast : 192.168.1.191 Usable Hosts : 192.168.1.129 - 192.168.1.190 (2^6 - 2 = 62 hosts) /24 = 255.255.255.0 -> 254 hosts /25 = 255.255.255.128 -> 126 hosts /30 = 255.255.255.252 -> 2 hosts (point-to-point links) /32 = 255.255.255.255 -> a single host

Port Address

A port address is a logical identifier (numeric value) for a specific process or service used to uniquely identify different communication endpoints in a network.

  • A port allows a single IP address to support multiple simultaneous communications, each using a different port number.
  • In a node, multiple processes are running, and data that is sent or received must reach the right process.
  • Every process in the node is uniquely identified using a port number, which is used to route data packets to the correct destination. This allows a device to distinguish between multiple running processes and applications when communicating.
  • Port numbers are assigned and managed by the Internet Assigned Numbers Authority (IANA).
  • Port numbers range from 0 to 65535.
Port Ranges
  • Well-Known Ports (0 - 1023) : Reserved for common services such as SSH (22), HTTP (80), and HTTPS (443). Binding to them usually requires admin/root privileges.
  • Registered Ports (1024 - 49151) : Assigned to specific applications, such as MySQL (3306) and RDP (3389).
  • Dynamic / Ephemeral Ports (49152 - 65535) : Temporarily assigned to the client side of a connection and released when it closes.
  • Socket : The combination of an IP address and a port, e.g. 192.168.1.10:443. A connection is uniquely identified by its 5-tuple: source IP, source port, destination IP, destination port, and protocol.

See the common ports table in Protocols.

Port Internals
  • Separate Spaces : TCP and UDP have independent port numbers, so TCP 53 and UDP 53 are different endpoints.
  • Ephemeral Ranges in Practice : Linux uses 32768 to 60999 by default (/proc/sys/net/ipv4/ip_local_port_range); Windows uses the IANA range 49152 to 65535.
  • Binding : a server listens on 0.0.0.0:port (all IPv4 interfaces), [::]:port, or one address such as 127.0.0.1:port (local only).
  • Scan Results : a port is open (a service answers), closed (the host replies with TCP RST), or filtered (a firewall drops the probe, so there is no reply).

DNS

The Domain Name System (DNS) is the phonebook of the Internet. Humans access information online through domain names, like google.com. Web browsers interact through IP addresses. DNS translates domain names to IP addresses so browsers can load Internet resources. DNS servers eliminate the need for humans to memorize IP addresses such as 192.168.1.1 (in IPv4).

  • Domain Name Resolution : When a domain name is entered into a web browser, the device first checks its local DNS cache to see if the corresponding IP address exists. If not, it sends a request to a DNS server.
  • DNS Server Lookup : The device sends a query to a DNS server, provided by the Internet Service Provider (ISP). If the DNS server has the requested information in its cache, it returns the IP address to the device. If not, it queries other DNS servers until it finds the information or determines that it doesn't exist.
  • Response : Once the DNS server has the IP address corresponding to the requested domain name, it sends that information back to the device. The device can then connect to the server hosting the requested website and access the website.

  • Domain Hierarchy : Domain Hierarchy refers to the structure and organization of domain names within the Domain Name System (DNS).

    page.example.com
    • Top-Level Domain (.com)
    • Second-Level Domain (example)
    • Subdomain (page)

  • DNS Records : DNS records are entries in a DNS database that map a domain name to specific data. These records provide information about how the internet should route traffic for a domain, such as how to find a website, where to send emails, and more. Each DNS record has a specific type and serves a unique purpose. DNS records ensure that DNS queries are directed to the correct server based on the domain name.

    Record Types
    • Address Record (A) : Maps a domain to an IPv4 address.
    • IPv6 Address Record (AAAA) : Maps a domain to an IPv6 address.
    • Canonical Name Record (CNAME) : Aliases one domain name to another.
    • Mail Exchange Record (MX) : Directs email traffic to a mail server for a domain.
    • Name Server Record (NS) : Specifies the authoritative name servers for the domain.
    • Service Record (SRV) : Specifies services available for a domain, including protocol and port number.
    • Pointer Record (PTR) : Maps an IP address to a domain name, typically used for reverse DNS lookups.
    • Text Record (TXT) : Used to store arbitrary text, often for verification purposes (like SPF, DKIM, or other services).
    • Start of Authority (SOA) : Holds administrative information about the zone, such as the primary name server, admin email, serial number, and refresh timers.
DNS Resolution Flow
Browser cache -> OS cache / hosts file -> Recursive Resolver (ISP, 8.8.8.8, 1.1.1.1) Resolver -> Root Server : "Where is .com?" -> .com TLD server Resolver -> .com TLD Server : "Where is example.com?" -> example.com name server Resolver -> Authoritative Server : "IP of www.example.com?" -> 203.0.113.10 Resolver -> Browser : 203.0.113.10 (cached for the record's TTL)
  • Recursive Resolver : Does the full lookup on the client's behalf and caches results. Provided by the ISP or public services like Google (8.8.8.8) and Cloudflare (1.1.1.1).
  • Root Servers : The top of the hierarchy. There are 13 named root server identities (a to m.root-servers.net), each run as many servers worldwide.
  • TLD Servers : Know the name servers for every domain under a top-level domain like .com or .org.
  • Authoritative Name Server : Holds the actual DNS records for a domain and gives the final answer.
  • TTL (Time To Live) : How long, in seconds, a record may be cached before it must be looked up again.
  • DNS uses UDP port 53, falling back to TCP for large responses and zone transfers. Encrypted variants are DNS over TLS (DoT, port 853) and DNS over HTTPS (DoH, port 443).
DNS Internals
  • Transport : UDP port 53. Classic DNS limits UDP responses to 512 bytes; EDNS(0) (RFC 6891) allows larger ones. A response that does not fit sets the TC (truncated) flag and the client retries over TCP 53.
  • Recursive vs Iterative : clients send a recursive query ("give me the final answer"); resolvers then send iterative queries to root, TLD, and authoritative servers ("tell me where to ask next").
  • Authoritative Answer : the AA flag marks an answer from the zone's own server; anything else came from a cache.
  • Negative Caching : an NXDOMAIN (name does not exist) answer is cached too, for the time set in the zone's SOA record (RFC 2308).
  • Zone Transfers : secondary servers copy a zone with AXFR (full) or IXFR (incremental) over TCP. Allow them only to your own secondaries, since an open transfer reveals every record.
Security Records & Extensions
Record / Feature Purpose
CAA lists the certificate authorities allowed to issue certificates for the domain
DNSKEY, RRSIG, DS, NSEC/NSEC3 DNSSEC: public keys, record signatures, the parent-zone link, and signed proof that a name does not exist
TXT (SPF, DKIM, DMARC) email authentication policies (see SMTP under Protocols)
DNS over TLS (RFC 7858) / DNS over HTTPS (RFC 8484) encrypt queries between the client and resolver for privacy

DNSSEC vs DoH/DoT : DNSSEC signs records so tampering is detectable (authenticity), but queries stay readable. DoT and DoH encrypt the queries (privacy) but do not prove the answer is genuine. They solve different problems and are used together.

URL

A URL (or Uniform Resource Locator) is predominantly an instruction on how to access a resource on the internet.

Example
http://user:password@example.com:80/view?id=1#task2
  • Scheme (http) : This instructs on what protocol to use for accessing the resource such as HTTP, HTTPS, FTP.
  • User (user:password) : Some services require authentication to log in; put a username and password into the URL to log in. This is deprecated and insecure, as credentials end up in browser history and logs.
  • Host (example.com) : The domain name or IP address of the server to access.
  • Port (80) : The port that the client is going to connect to, usually 80 for HTTP and 443 for HTTPS.
  • Path (/view) : The file name or location of the resource that is to be accessed.
  • Query String (?id=1) : Extra bits of information that can be sent to the requested path.
  • Fragment (#task2) : This is a reference to a location on the actual page requested.
URI vs URL vs URN
  • URI (Uniform Resource Identifier) : Any string that identifies a resource. URL and URN are both types of URI.
  • URL (Uniform Resource Locator) : Identifies a resource by where it is and how to access it, e.g. https://example.com/docs.
  • URN (Uniform Resource Name) : Identifies a resource by a unique name, without a location, e.g. urn:isbn:0451450523.

Every URL is a URI, but not every URI is a URL.

URL Encoding & Resolution
  • Percent-Encoding (RFC 3986) : characters outside the allowed set are sent as %XX UTF-8 bytes, e.g. café becomes caf%C3%A9 and a space becomes %20 (or + in form-encoded query strings).
  • Reserved Characters : : / ? # [ ] @ ! $ & ' ( ) * + , ; = have special meaning and must be encoded when used as data.
  • The Fragment Stays in the Browser : everything after # is never sent to the server.
  • Internationalized Domains : non-ASCII names are converted to Punycode, e.g. münchen.de becomes xn--mnchen-3ya.de. Look-alike characters from other alphabets enable homograph phishing, which browsers counter by showing Punycode for mixed scripts.

World Wide Web (WWW)

The World Wide Web (WWW, or simply "the Web") is a system of interlinked documents and resources, such as web pages, images, and videos, that are identified by URLs, transferred using HTTP/HTTPS, and viewed in web browsers. It was invented by Tim Berners-Lee at CERN in 1989, and the first website went live in 1991. Web standards are developed by the World Wide Web Consortium (W3C) and WHATWG.

Internet vs Web : The Internet is the global network of connected devices (the infrastructure). The Web is one service that runs on top of the Internet, alongside others like email, FTP, SSH, and online gaming.
Building Blocks of the Web
  • HTML : The markup language that structures web pages; CSS styles them and JavaScript makes them interactive.
  • URL : The unique address of every resource on the Web (see URL).
  • HTTP / HTTPS : The protocol browsers and servers use to request and deliver resources (see HTTP Protocol).
  • Hyperlinks : Links that connect one resource to another, forming the "web" of documents.
  • Web Browser : The client software that requests, renders, and displays web pages (Chrome, Firefox, Safari, Edge).
  • Web Server : Stores and serves the resources (see Web Server).

The "www" in a Domain

The www in www.example.com is just a subdomain, a naming convention from the early Web that marked the host serving web pages. It is not required: example.com and www.example.com are separate DNS names that usually point to the same site, with one redirecting to the other (301) so there is a single canonical address. A www subdomain can use a CNAME record (for example, pointing to a CDN), which the root domain cannot.

Evolution of the Web
  • Web 1.0 (Static Web) : Early 1990s to early 2000s. Read-only static HTML pages; few creators, many readers.
  • Web 2.0 (Social Web) : Mid-2000s onward. Interactive web apps, social media, and user-generated content (read-write).
  • Web 3.0 / Web3 : Used for two ideas: the Semantic Web (machine-readable, linked data) and the decentralized Web built on blockchains, where users own their data and assets (read-write-own).
Layers of the Web
  • Surface Web : Public pages indexed by search engines, such as news sites, blogs, and online stores. Only a small fraction of all web content.
  • Deep Web : Content not indexed by search engines: anything behind a login, paywall, or private database, such as email inboxes and bank dashboards. Mostly ordinary and legal.
  • Dark Web : Intentionally hidden sites that need special software like Tor to access (see TOR).
How the Browser Renders a Page
  1. Parse HTML : builds the DOM tree. A normal <script> pauses parsing until it downloads and runs; defer and async avoid that.
  2. Parse CSS : builds the CSSOM. CSS blocks rendering, since the page cannot be painted without styles.
  3. Render Tree : DOM + CSSOM, containing only visible elements.
  4. Layout (Reflow) : calculates the size and position of every element.
  5. Paint & Composite : draws pixels into layers, which the GPU combines on screen.
Same-Origin Policy & CORS

The Same-Origin Policy stops a page from reading responses from a different origin (scheme + host + port). It is the browser's core isolation boundary: a malicious site can send requests to your bank, but it cannot read the replies. CORS (Cross-Origin Resource Sharing) lets a server explicitly allow chosen origins to read its responses.

  • Simple Requests : GET, HEAD, or POST with standard form content types skip the preflight; the browser still checks Access-Control-Allow-Origin on the response.
  • Credentials : with cookies (Allow-Credentials: true) the server must name an exact origin; the wildcard * is not allowed.
  • Not a Server Defense : CORS only controls what browsers let scripts read. Tools like curl ignore it, so it never replaces authentication.
  • Common Mistake : reflecting any Origin back with credentials allowed lets every website read users' private data.

OSI Model

The Open Systems Interconnection (OSI) model is a reference model from the International Organization for Standardization (ISO) that provides a common basis for the coordination of standards development for the purpose of systems interconnection. In the OSI reference model, the communications between systems are split into seven different abstraction layers that computer systems use to communicate over a network. The modern Internet is not based on OSI but on the simpler TCP/IP model.

  • Application Layer

    The application layer is used by end-user software such as web browsers and email clients. It provides protocols that allow software to send and receive information and present meaningful data to users. A few examples of application layer protocols are HTTP, FTP, POP, SMTP, and DNS.

  • Presentation Layer

    The presentation layer prepares data for the application layer. It defines how two devices should encode, encrypt, and compress data so it is received correctly on the other end. The presentation layer takes any data transmitted by the application layer and prepares it for transmission over the session layer.

  • Session Layer

    The session layer creates communication channels, called sessions, between devices. It is responsible for opening sessions, ensuring they remain open and functional while data is being transferred, and closing them when communication ends.

  • Transport Layer

    The transport layer takes data transferred in the session layer and breaks it into “segments” on the transmitting end. It is responsible for reassembling the segments on the receiving end, turning it back into data that can be used by the session layer.

  • Network Layer

    The network layer has two main functions. One is breaking up segments into network packets, and reassembling the packets on the receiving end. The other is routing packets by discovering the best path across a physical network. The network layer uses network addresses (typically Internet Protocol addresses) to route packets to a destination node.

  • Data Link Layer

    The data link layer establishes and terminates a connection between two physically-connected nodes on a network. It breaks up packets into frames and sends them from source to destination.

  • Physical Layer

    The physical layer is responsible for the physical cable or wireless connection between network nodes. It defines the connector, the electrical cable or wireless technology connecting the devices, and is responsible for the transmission of the raw data.

TCP/IP Model

The Internet protocol suite, commonly known as TCP/IP, is a framework for organizing the set of communication protocols used in the Internet and similar computer networks according to functional criteria. The foundational protocols in the suite are the Transmission Control Protocol (TCP), the User Datagram Protocol (UDP), and the Internet Protocol (IP). The Internet protocol suite provides end-to-end data communication specifying how data should be packetized, addressed, transmitted, routed, and received. This functionality is organized into four abstraction layers, which classify all related protocols according to each protocol's scope of networking.

  • Application Layer

    The application layer is the top layer and provides applications with standardized data exchange. Its protocols include HTTP, FTP, POP3, SMTP, DNS, DHCP and SNMP. At the application layer, the payload is the actual application data.

  • Transport Layer

    The transport layer is responsible for maintaining end-to-end communications across the network. TCP handles communications between hosts and provides flow control, multiplexing and reliability. The transport protocols include TCP and UDP.

  • Internet Layer

    The internet layer, also called the network layer, deals with packets and connects independent networks to transport the packets across network boundaries. The network layer protocols are IP and Internet Control Message Protocol (ICMP), which are used for error reporting.

  • Network Access Layer

    The network Access layer, also known as the network interface layer or data link layer, consists of protocols that operate only on a link -- the network component that interconnects nodes or hosts in the network. The protocols in this lowest layer include Ethernet for local area networks and Address Resolution Protocol (ARP).

Protocols

In computer networking, protocols are a set of rules or conventions that govern how data is transmitted between devices on a network.
There are numerous protocols at different layers of the networking stack, such as -

  • Internet Protocol (IP)

    Fundamental protocol responsible for addressing and routing packets of data so they can travel across networks and reach their intended destinations.

  • Internet Control Message Protocol (ICMP)

    A network layer protocol used to send error messages and diagnostic information, such as "destination unreachable" or "time exceeded". The ping and traceroute tools are built on ICMP.

  • Transmission Control Protocol (TCP)

    TCP is a protocol that operates at a higher level than IP and is responsible for establishing and maintaining connections between devices, ensuring reliable and ordered delivery of data. If data is lost or corrupted during transmission, TCP detects this and retransmits the lost or corrupted packets. TCP is connection-oriented, meaning a connection is established and maintained until the application programs at each end have finished exchanging messages. This connection's establishment and termination involve a handshake process. TCP is used in web browsers (in HTTP), email, file transfer, and instant/realtime messaging.

  • User Datagram Protocol (UDP)

    UDP is a connectionless protocol, which means it doesn't establish a connection before sending data and doesn't guarantee delivery of packets or the order of packets. Each UDP packet is independent of the others. UDP offers lower latency compared to TCP due to its connectionless nature, no handshake, minimal overhead, and no retransmissions. It is often used for time-sensitive applications where speed is prioritized over reliability. UDP is commonly used in VoIP applications, video streaming, online gaming, DNS, and DHCP.

  • Hypertext Transfer Protocol (HTTP)

    The HTTP (Hypertext Transfer Protocol) is an application layer protocol used for transferring hypermedia documents, such as HTML files, on the World Wide Web. It is the foundation of data communication on the web, and HTTP uses a client-server model, where clients initiate requests and servers respond with the requested resources. HTTP operates over TCP/IP, which ensures reliable delivery of data packets over networks. The protocol is stateless, meaning each request from a client is independent and not dependent on previous requests.

  • Hypertext Transfer Protocol Secure (HTTPS)

    HTTPS (Hypertext Transfer Protocol Secure) is an extension of HTTP used for secure communication over a computer network, particularly the internet. It encrypts the data sent and received between a user's browser and the website server, ensuring that the information remains confidential and protected from interception or tampering by unauthorized parties. HTTPS uses SSL/TLS (Secure Sockets Layer/Transport Layer Security) protocols to establish an encrypted connection between the client and the server.

  • Simple Mail Transfer Protocol (SMTP)

    SMTP, or Simple Mail Transfer Protocol, is a communication protocol used for transmitting electronic mail (email) between computers over a network. It defines how email messages should be formatted and transmitted.

  • POP3 & IMAP

    Protocols for retrieving email from a mail server (SMTP only sends). POP3 (Post Office Protocol) downloads messages to one device and usually deletes them from the server. IMAP (Internet Message Access Protocol) keeps mail on the server and syncs it across all devices, which is why most modern clients use IMAP.

  • File Transfer Protocol (FTP)

    FTP, or File Transfer Protocol, is a standard network protocol used for transferring files between a client and a server on a computer network. It specifies how files should be transferred and accessed.

  • Secure Shell Protocol (SSH)

    SSH, or Secure Shell, is a cryptographic network protocol used to securely access and manage remote servers or systems over an unsecured network. It provides a secure channel over which users can perform various tasks, such as logging into remote machines, executing commands, transferring files, managing network services, and tunneling or port forwarding.

  • Telnet

    An old protocol for remote command-line access that sends everything, including passwords, in plain text. It has been replaced by SSH and should not be used over untrusted networks.

  • Simple Network Management Protocol (SNMP)

    Used to monitor and manage network devices such as routers, switches, and printers, by reading metrics like bandwidth usage, uptime, and errors. SNMPv3 adds authentication and encryption; older versions rely on plain-text "community strings".

  • Dynamic Host Configuration Protocol (DHCP)

    It is a network management protocol used to automatically assign IP addresses and other network configuration information to devices on a network. DHCP eliminates the need for manual configuration of network settings.

  • Network Time Protocol (NTP)

    NTP is a protocol used to synchronize the clocks of computers and other devices over a network. It ensures that systems maintain accurate time by synchronizing with a reference time source, typically an atomic clock or GPS time.

  • Ethernet

    Ethernet is a family of protocols that specify how devices on the same network segment format and transmit data over a physical medium. It is the standard way to connect devices in a wired network using cables and switches.

  • BitTorrent

    BitTorrent is a peer-to-peer (P2P) file-sharing protocol that allows users to distribute files efficiently across the internet. Instead of downloading a file from a single source, BitTorrent splits the file into smaller pieces and downloads them simultaneously from multiple sources (peers).

BitTorrent

BitTorrent is a peer-to-peer (P2P) file-sharing protocol used for distributing large amounts of data over the internet. Instead of downloading a file from a single server, BitTorrent breaks the file into smaller pieces and distributes them across a network of computers (peers) that share parts of the file. These peers download and upload pieces of the file to each other, enabling faster and more efficient transfers. It is used to efficiently share large files, reduce server load, enable faster downloads, and improve scalability and fault tolerance.

Key Concepts
  • Peers : The individual computers or devices connected to the BitTorrent network that share files with one another.
  • Seeders : Peers that have the complete file and share it with others.
  • Leechers : Peers that are downloading the file but haven’t completed downloading it yet. They usually also upload parts of the file they've downloaded.
  • Torrent File : A small file with the .torrent extension that contains metadata about the files to be shared (such as file names, sizes, and structure) and the addresses of tracker servers.
  • Trackers : Servers that help manage communication between peers. They don’t host the file but help peers find each other to facilitate data sharing.
  • Swarm : The group of all peers (seeders and leechers) sharing a specific file in the BitTorrent network.
  • Pieces and Blocks : Files are divided into smaller pieces, which are further subdivided into blocks. This allows users to download parts of a file from multiple peers simultaneously, making downloads faster and more efficient.
Protocol Details
  • Info Hash : a SHA-1 hash (BitTorrent v1) or SHA-256 (v2) of the torrent's info dictionary, which uniquely identifies the content.
  • Piece Verification : the torrent file stores a hash of every piece, so corrupted or tampered pieces from a peer are detected and downloaded again.
  • Magnet Links : magnet:?xt=urn:btih:<info-hash>&dn=name&tr=<tracker> carries only the info hash; the metadata is fetched from peers.
  • DHT & PEX : a Kademlia-based distributed hash table and peer exchange find peers without a central tracker.
  • Piece Selection : clients download the rarest pieces first, so every piece stays available in the swarm.
  • Tit-for-Tat : peers upload to ("unchoke") the peers that upload to them the fastest, which rewards sharing.
  • Transport : TCP, or uTP over UDP to avoid congesting the user's connection; traditionally ports 6881 to 6889.

HTTP Protocol

The HTTP (Hypertext Transfer Protocol) is an application layer protocol used for transferring hypermedia documents, such as HTML files, on the World Wide Web. It is the foundation of data communication on the web: clients (usually browsers) send requests and servers respond with the requested resources.

Key Characteristics
  • Client-Server : The client always starts the exchange with a request; the server only responds.
  • Stateless : Each request is independent; the server does not remember previous requests by default. Cookies and sessions add state on top.
  • Runs over TCP : HTTP/1.x and HTTP/2 use TCP (port 80) for reliable delivery; HTTP/3 uses QUIC over UDP.
  • Text-Based (HTTP/1.x) : Requests and responses are human-readable text; HTTP/2 and HTTP/3 use a binary format.
  • HTTPS : HTTP over an encrypted TLS connection (port 443), so data cannot be read or changed in transit. Always use it for logins, cookies, and personal data.
  • Message Format : a start line (request line METHOD target VERSION, or status line VERSION code reason), header fields (Name: value), an empty line (CRLF), then an optional body.
  • Version Negotiation : HTTP/2 is agreed during the TLS handshake through ALPN (h2); servers advertise HTTP/3 with the Alt-Svc: h3=":443" header.
  • Specifications : semantics in RFC 9110, caching in RFC 9111, HTTP/1.1 in RFC 9112, HTTP/2 in RFC 9113, HTTP/3 in RFC 9114.

HTTP Headers

Headers are additional bits of data that are sent to the web server when making requests. Although no headers are strictly required when making an HTTP request, if they are not sent, it is difficult to view a website properly.

  • Common Request Headers
    • Host : Some web servers host multiple websites, so by providing the host headers, the client instructs the server which one is required; otherwise, it receives the default website for the server.
    • User-Agent : This is the browser software and its version number, which tells the web server which browser is being used, helping it format the website properly for that specific browser. Additionally, some elements of HTML, JavaScript, and CSS are only supported in certain browser versions.
    • Content-Length : When sending data to a web server, such as in a form, the content length tells the web server how much data to expect in the web request. This way, the server can ensure it isn't missing any data.
    • Accept-Encoding : Tells the web server what types of compression methods the browser supports so the data can be made smaller for transmitting over the internet.
    • Cookie : It is data that is sent to the server to help remember users information.
    • Authorization : Carries credentials for the request, such as Bearer <token> or Basic authentication.
  • Common Response Headers
    • Set-Cookie : Information to store as cookie, which gets sent back to the web server on each request.
    • Cache-Control : How long should it take to store the content of the response in the browser's cache before it requests it again.
    • Content-Type : This tells the client what type of data is being returned, i.e., HTML, CSS, JavaScript, images, PDF, video, etc. Using the content-type header, the browser then knows how to process the data.
    • Content-Encoding : What method has been used to compress the data to make it smaller when sending it over the internet.
    • Location : The URL to go to next, sent with redirects (3xx) and with 201 Created.
HTTP Body (Payload)

The body is the actual data carried by an HTTP message. Requests usually carry one with POST, PUT, and PATCH; responses carry the content returned, such as HTML, JSON, images, or files. Its format is declared by Content-Type and its size by Content-Length.

POST /login HTTP/1.1 Host: example.com Content-Type: application/json Content-Length: 43 {"username":"prime","password":"secret123"} HTTP/1.1 200 OK Content-Type: application/json Content-Length: 40 {"status":"success","token":"abc123xyz"}
Common Uses
  • Form submissions (application/x-www-form-urlencoded, multipart/form-data).
  • API calls with structured data (JSON, XML, GraphQL).
  • File uploads and downloads (images, PDFs) and streaming (video, audio).
Framing & Content Negotiation
  • Content-Length : the exact body size in bytes, so the receiver knows where the message ends.
  • Transfer-Encoding: chunked (HTTP/1.1) : the body is sent in chunks, each prefixed with its size in hex, and ends with a zero-length chunk. Used when the size is not known up front. HTTP/2 and HTTP/3 do not use it, since their framing marks message boundaries.
  • Content Negotiation : the client lists what it accepts (Accept, Accept-Language, Accept-Encoding); the server answers with Content-Type and Content-Encoding (gzip, br) and lists the headers it varied on in Vary.
  • multipart/form-data : file uploads split the body into parts separated by the boundary string declared in Content-Type.
Security Risks
  • Injection : SQL, NoSQL, or command injection when body data is used without validation.
  • XSS : malicious content that is stored and later returned to other users.
  • CSRF : a forged request that the browser sends with the victim's cookies.
  • Sensitive Data Exposure : passwords, tokens, or personal data sent over plain HTTP.
  • Insecure Deserialization : crafted objects that run code when the server deserializes them.
  • Malicious Uploads : files that lead to remote code execution if stored and executed.
Best Practices
  • Use HTTPS so bodies are encrypted in transit.
  • Validate and sanitize all input on the server, and check that Content-Type matches the data.
  • Limit body size to prevent denial of service with oversized requests.
  • Check uploaded files by type, size, and extension, and store them outside the web root.

Cookies

A cookie is a small piece of data that a web server asks the browser to store, using the Set-Cookie response header. The browser then sends it back automatically with later requests to the same site, which lets a stateless protocol remember things such as a logged-in user. Each cookie is a name-value pair of up to about 4 KB, and browsers also limit how many cookies one domain can store.

# Server -> browser: store a cookie Set-Cookie: session=abc123; Max-Age=3600; Path=/; Secure; HttpOnly; SameSite=Lax # Browser -> server: sent with every matching request Cookie: session=abc123; theme=dark
Types of Cookies
  • Session Cookie : No Expires or Max-Age; deleted when the browser closes.
  • Persistent Cookie : Kept until its expiry date, even across browser restarts.
  • First-Party Cookie : Set by the site in the address bar.
  • Third-Party Cookie : Set by another domain embedded in the page (ads, trackers). Safari and Firefox block them by default, and other browsers increasingly restrict them.
Common Uses
  • Session Management : keeping a user logged in (see Sessions).
  • Preferences : language, theme, cart contents.
  • Tracking & Analytics : recognizing returning visitors and measuring behavior.
  • Advertising : personalizing ads across sites.

Cookie Prefixes : A name starting with __Secure- must have Secure; one starting with __Host- must also have Path=/ and no Domain, which locks it to a single host.

Domain & Subdomain Scope
  • No Domain attribute (host-only) : Sent only to the exact host that set it. A cookie from example.com does not reach app.example.com.
  • Domain=example.com : Sent to example.com and all its subdomains (app.example.com, shop.example.com).
  • Set by a subdomain (app.example.com) : By default it stays on that subdomain, hidden from the parent and sibling subdomains. The subdomain can choose Domain=example.com to share it with all of them.
  • Limits : A site cannot set cookies for an unrelated domain or for a public suffix such as .com or .co.uk.
How Browsers Handle Cookies
  • Standard : RFC 6265, being updated by the RFC 6265bis draft. The browser keeps cookies in a cookie jar, where each cookie is identified by its name, domain, and path.
  • One Cookie per Header : each Set-Cookie header sets exactly one cookie. The browser sends all matching cookies together in a single Cookie header, separated by ; .
  • Matching Rules : a cookie is attached only when the request host domain-matches, the request path starts with the cookie's Path, it has not expired, the connection is HTTPS if it is Secure, and SameSite allows the request context.
  • Expiry : Max-Age (seconds) takes precedence over Expires (an HTTP date). Max-Age=0 or a past Expires deletes the cookie.
  • Site vs Origin : SameSite compares sites: the scheme plus the registrable domain (eTLD+1, decided by the Public Suffix List). app.example.com and shop.example.com are same-site but cross-origin.
  • Size Limits : RFC 6265 requires browsers to support at least 4096 bytes per cookie (name + value), 50 cookies per domain, and 3000 cookies in total.
  • JavaScript Access : document.cookie returns only name=value pairs (no attributes) and never includes HttpOnly cookies.
  • Partitioned (CHIPS) : the Partitioned attribute stores a third-party cookie in a separate jar per top-level site, so an embed can keep state without tracking users across sites.
Misconfiguration Risks
  • Missing HttpOnly : session cookies can be stolen through XSS.
  • Missing Secure : cookies can be read on unencrypted connections.
  • Weak or missing SameSite : requests are easier to forge with CSRF.
  • Too-broad Domain or Path : cookies leak to subdomains or paths that should not see them.
  • Sensitive data in cookies : cookies are readable on the user's device, so store an ID and keep the data on the server.
  • Long lifetimes : a stolen persistent session cookie stays usable until it expires.

Sessions

A session is the period of interaction between a client and a web application that lasts across many requests. Because HTTP is stateless, the server uses a session to remember who the user is and what they are doing, without asking them to log in on every page.

How Sessions Work
  1. Login : The user submits a username and password, and the server verifies them.
  2. Create Session : The server creates a session record and a long, random session ID.
  3. Send ID : The ID is returned in a cookie, e.g. Set-Cookie: SESSIONID=8f3a...; HttpOnly; Secure.
  4. Later Requests : The browser sends the cookie automatically with every request.
  5. Look Up : The server finds the session by its ID and knows the user, their role, and their state.
  6. End : The session is destroyed on logout or when it times out.
POST /login -> 200 OK Set-Cookie: SESSIONID=8f3a9c; HttpOnly; Secure; SameSite=Lax GET /inbox -> server looks up SESSIONID=8f3a9c Cookie: SESSIONID=8f3a9c -> user=prime, role=user -> 200 OK (the user's inbox)

Common session cookie names: JSESSIONID (Java), PHPSESSID (PHP), ASP.NET_SessionId (.NET), connect.sid (Express).

What a Session Stores
  • User identity (user ID) and roles or permissions.
  • Application state: cart items, multi-step form progress, an OTP flow.
  • Server-side : in memory, a database, or a session store such as Redis.
  • Client-side : in a signed cookie or a token such as a JWT (stateless sessions).
Server-Side Session Stores
  • In-Memory : fastest, but sessions are lost on restart and exist on one server only.
  • Redis / Memcached : a shared key-value store with a TTL per session, e.g. SET sess:8f3a9c '{"uid":7,"role":"user"}' EX 1800 (expires after 30 minutes).
  • Database : durable, but slower; expired rows need cleaning up.
  • Load Balancing : either sticky sessions (the load balancer pins a user to one server) or, preferably, a shared store that every server can read.

  • Structure : header.payload.signature, each part Base64URL-encoded. Signed with HS256 (shared secret) or RS256 / ES256 (private key signs, public key verifies). The payload is readable by anyone; only the signature prevents tampering.
  • Registered Claims : iss (issuer), sub (subject), aud (audience), exp (expiry), iat (issued at), nbf (not before), jti (unique token ID).

Session Security

A session ID represents the user's identity: anyone who steals it becomes that user.

  • Session Hijacking : an attacker steals the ID through XSS, an unencrypted connection, or logs. Defend with HttpOnly, Secure, HTTPS everywhere, and never putting the ID in a URL.
  • Session Fixation : an attacker plants a known session ID before the victim logs in. Defend by issuing a new session ID right after login.
  • CSRF : another site makes the browser send a request with the victim's session cookie. Defend with SameSite and anti-CSRF tokens.
  • Strong IDs : at least 64 bits of entropy (OWASP), typically a 128-bit value from a CSPRNG encoded as hex or Base64URL, so IDs cannot be guessed or brute-forced.
  • Timeouts : an idle timeout plus an absolute maximum lifetime; destroy the session on the server at logout, not only the cookie.

Web applications keep data in several places, from the browser to the server. Client-side storage lets a site remember data on the user's device without sending it to the server on every request.

An origin is the scheme, host, and port together: https://app.example.com:443. http:// and https:// versions of a site, or two subdomains, have separate storage.

Types of Client-Side Storage
  • localStorage : Simple key-value storage (window.localStorage) that persists until cleared. Used for UI preferences, theme, and saved drafts.
  • sessionStorage : The same API, but data lives only while the tab is open; it survives reloads but not closing the tab, and each tab has its own copy. Used for one-tab state such as a form in progress.
  • IndexedDB : A transactional NoSQL database in the browser for large or structured data, including files. Used by offline apps and large caches.
  • Cache Storage : Stores full HTTP responses (HTML, CSS, JS, images), managed by Service Workers to make Progressive Web Apps (PWAs) work offline.
  • In-Memory (JavaScript variables) : The fastest, but lost on page reload or navigation. Used for temporary runtime data.
  • Web SQL : A SQL database API that was deprecated and has been removed from modern browsers; do not use it.
Example
localStorage.setItem("theme", "dark"); // save localStorage.getItem("theme"); // "dark" localStorage.removeItem("theme"); // delete one key localStorage.clear(); // delete everything for this origin // Values are strings: store objects as JSON localStorage.setItem("user", JSON.stringify({ name: "Prime", id: 7 })); const user = JSON.parse(localStorage.getItem("user")); sessionStorage.setItem("step", "2"); // same API, cleared when the tab closes
Web Storage API (localStorage & sessionStorage)
  • Interface : both implement Storage: length, key(n), getItem(), setItem(), removeItem(), clear().
  • Synchronous : every call blocks the main thread, so it suits small values only. It is not available in Web Workers.
  • Strings Only : keys and values are stored as strings; numbers and objects must be converted (e.g. with JSON).
  • Quota Errors : setItem() throws a QuotaExceededError when the origin's quota is full.
  • storage Event : fires in other open documents of the same origin when localStorage changes, which lets tabs stay in sync.
  • sessionStorage Scope : one store per tab (top-level browsing context) and origin; duplicating a tab copies it, and it survives reloads.
IndexedDB
  • Structure : a database contains object stores (like tables), each with a primary key (keyPath or auto-increment) and optional indexes for querying.
  • Versioned Schema : stores and indexes can only be created or changed in the onupgradeneeded handler when the database version increases.
  • Transactions : every read and write runs in a transaction: readonly, readwrite, or versionchange (schema upgrades).
  • Structured Clone : values are copied with the structured clone algorithm, so objects, arrays, dates, Blob, File, and ArrayBuffer work, but functions and DOM nodes do not.
  • Asynchronous : request and event based (often wrapped in promises with a library such as idb), and available in Web Workers and Service Workers.
const request = indexedDB.open("notes-db", 1); // name, version request.onupgradeneeded = () => { request.result.createObjectStore("notes", { keyPath: "id" }); }; request.onsuccess = () => { const tx = request.result.transaction("notes", "readwrite"); tx.objectStore("notes").put({ id: 1, text: "Hello" }); tx.oncomplete = () => console.log("saved"); };
Cache Storage
  • Stores Request / Response pairs: caches.open(name), then cache.put(), cache.match(), cache.delete().
  • Commonly used in a Service Worker's fetch handler to serve responses from cache and work offline.
Quota & Eviction
  • Estimate : await navigator.storage.estimate() returns the origin's usage and quota.
  • Best-Effort vs Persistent : by default storage is best-effort and the browser may evict it under storage pressure, least recently used origin first. navigator.storage.persist() asks for persistent storage that is only removed by the user.
  • Private Browsing : all client-side storage is discarded when the private session ends.
  • Safari (ITP) : script-writable storage of a site the user has not interacted with for 7 days may be deleted.
Security Notes
  • Any script on the page can read it : an XSS attack can steal everything in localStorage or sessionStorage, so do not store session tokens or passwords there. An HttpOnly cookie is safer for session tokens.
  • Not encrypted : data is stored as plain text on the user's device.
  • Not trusted input : users can edit their own storage, so validate anything read back before using it.

Web Socket

A Web Socket is a communication protocol that provides full-duplex communication and a persistent connection over a single TCP connection between a client (a web browser) and a server. Unlike HTTP's request-response model, either side can send messages at any time with very little overhead, which makes it ideal for real-time apps.

How It Works

A WebSocket connection starts as a normal HTTP request asking to upgrade the connection. This lets it pass through existing HTTP infrastructure and proxies.

# Client -> server GET /chat HTTP/1.1 Host: example.com Upgrade: websocket Connection: Upgrade Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ== Sec-WebSocket-Version: 13 Origin: https://example.com # Server -> client HTTP/1.1 101 Switching Protocols Upgrade: websocket Connection: Upgrade Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo=
  • 101 Switching Protocols : After this response, the same TCP connection carries WebSocket frames in both directions until either side closes it.
  • ws:// and wss:// : ws is unencrypted (port 80); wss runs over TLS (port 443) like HTTPS. Always use wss in production.
  • Frames : Messages are sent as text or binary frames, with ping/pong frames to keep the connection alive and a close frame to end it (see the frame structure below).
  • Accept Key : Sec-WebSocket-Accept = Base64(SHA-1(Sec-WebSocket-Key + 258EAFA5-E914-47DA-95CA-C5AB0DC85B11)). It proves the server understood the WebSocket handshake; it is not authentication.
  • Subprotocols & Extensions : Sec-WebSocket-Protocol negotiates an application protocol (e.g. graphql-ws, mqtt); Sec-WebSocket-Extensions negotiates extensions such as permessage-deflate compression (RFC 7692).
  • Standards : defined in RFC 6455; WebSockets over HTTP/2 use extended CONNECT (RFC 8441).
Frame Structure
  • FIN : 1 bit, set on the last fragment of a message.
  • Opcode : 4 bits, the frame type (table below).
  • MASK + Masking Key : every client-to-server frame must be XOR-masked with a random 32-bit key, which prevents cache-poisoning attacks on intermediaries; server-to-client frames are not masked.
  • Payload Length : 7 bits for 0 to 125 bytes; the value 126 adds a 16-bit length, 127 adds a 64-bit length.

  • readyState : 0 CONNECTING, 1 OPEN, 2 CLOSING, 3 CLOSED. Only call send() when it is OPEN.
  • bufferedAmount : bytes queued by send() but not yet transmitted; check it to apply backpressure.
  • binaryType : how binary messages arrive: "blob" (default) or "arraybuffer".
  • No Custom Headers : the browser API cannot set headers such as Authorization. Authenticate with a cookie, a subprotocol value, or a short-lived token in the first message (a token in the URL query leaks into logs).

Libraries: ws (Node.js server) and Socket.IO, which adds rooms, automatic reconnection, and fallbacks but uses its own protocol on top of WebSocket.

Use Cases
  • Chat and social media notifications.
  • Online gaming and live streaming.
  • Live dashboards, stock and sports tickers.
  • Collaborative tools like Google Docs.
Security

WebSockets carry user actions and sensitive data just like HTTP, so almost every web vulnerability that affects HTTP can also affect WebSocket traffic.

  • Cross-Site WebSocket Hijacking (CSWSH) : the browser sends cookies with the handshake, and WebSockets are not limited by the same-origin policy or CORS, so a malicious site can open a socket as the logged-in user. Check the Origin header on the server and use a CSRF token or ticket in the handshake.
  • Authenticate the Handshake : verify the user when the connection opens, and re-check permissions for sensitive messages.
  • Validate Every Message : treat message contents like any user input to prevent injection and XSS.
  • Encrypt : use wss:// so messages cannot be read or altered in transit.
  • Limit Abuse : cap message size, connection count, and message rate to prevent denial of service.

Web Server

A web server is software (and the machine running it) that listens for HTTP/HTTPS requests from clients, usually browsers, and responds with web content such as HTML pages, images, CSS, and JavaScript files. When a browser requests a URL, the web server locates the resource, applies its configuration rules, and sends back the response along with a status code and headers. Examples: Apache HTTP Server, NGINX, Microsoft IIS, LiteSpeed, and Caddy.

  • Static Content : Files served exactly as stored on disk, such as HTML, images, and stylesheets. Web servers are extremely fast at this.
  • Dynamic Content : Content generated per request. The web server passes the request to an application server or runtime (PHP-FPM, Node.js, Python WSGI servers like Gunicorn) and returns the generated response to the client.
  • Web Server vs Application Server : A web server handles HTTP itself: accepting connections, TLS, serving files, and routing. An application server runs the business logic of an application. In practice they are often combined, with the web server in front acting as a reverse proxy to the application server, for example NGINX in front of a Node.js or Django app.
  • Common Features : Virtual hosting (serving multiple websites from one server), TLS/SSL termination, compression (gzip, Brotli), caching, access logs, URL rewriting, and directory access control.
  • Web servers listen on port 80 for HTTP and port 443 for HTTPS by default.
Architecture
  • Process / Thread per Connection : Apache's prefork and worker models; simple, but each connection uses memory.
  • Event-Driven : NGINX (and Apache's event model) handle thousands of connections per worker with non-blocking I/O, which solved the "C10k" problem.
  • Virtual Hosting : one IP serves many sites, chosen by the HTTP Host header and, for HTTPS, the TLS SNI hostname.
Example: NGINX as a Reverse Proxy
server { listen 443 ssl; server_name example.com; ssl_certificate /etc/ssl/certs/example.pem; ssl_certificate_key /etc/ssl/private/example.key; server_tokens off; # hide the version number location /static/ { root /var/www; # serve files from /var/www/static/ } location / { proxy_pass http://127.0.0.1:3000; # forward to the app server proxy_set_header Host $host; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } }

Load Balancer

A load balancer is a device or software that distributes incoming network traffic across multiple backend servers so that no single server becomes a bottleneck or a single point of failure. It sits between clients and the server pool, forwards each request to a healthy server, and removes servers from rotation when health checks fail. This improves availability, scalability, and performance. Examples: NGINX, HAProxy, AWS Elastic Load Balancer, Cloudflare Load Balancing.

Types of Load Balancers
  • Layer 4 (Transport Level) : Balances traffic based on IP address and TCP/UDP port without looking at the content. It is very fast and protocol-agnostic. Example: AWS Network Load Balancer.
  • Layer 7 (Application Level) : Understands HTTP and can route based on the URL path, hostname, headers, or cookies. This enables smarter routing, such as sending /api traffic to one server group and /images to another. Example: AWS Application Load Balancer, NGINX.
  • Hardware vs Software : Hardware load balancers are dedicated appliances (F5, Citrix ADC), while software load balancers run on standard servers or as cloud services.
Load Balancing Algorithms
  • Round Robin : Requests are distributed to servers one after another in order. Simple and effective when servers are equal.
  • Weighted Round Robin : Like round robin, but stronger servers receive proportionally more requests.
  • Least Connections : Each new request goes to the server with the fewest active connections. Useful when request durations vary.
  • IP Hash : The client's IP address determines which server it lands on, so the same client keeps hitting the same server. This provides basic session persistence (sticky sessions).
  • Health Checks : The load balancer periodically probes each server (for example, requesting /health). Servers that fail are taken out of rotation until they recover.
  • Failover & High Availability : With servers in multiple zones behind a load balancer, traffic automatically shifts away from a failed server or zone. Application: A website running 3 identical app servers behind an NGINX load balancer, where a deploy restarts one server at a time and users never notice.
Technical Details
  • Session Persistence : "sticky sessions" pin a client to one server using a load balancer cookie or a hash of the source IP. A shared session store makes it unnecessary.
  • TLS Termination vs Passthrough : termination decrypts at the load balancer so it can route by URL and offload crypto work; passthrough forwards encrypted traffic (Layer 4) so only the backend holds the certificate.
  • Health Check Types : TCP connect, an HTTP request expecting a 200, or a custom script, run on an interval with a failure threshold before a server is removed.
  • Consistent Hashing : maps clients to servers so that adding or removing a server moves only a small share of clients, which keeps caches warm.
  • Global Load Balancing : DNS-based (GSLB) or anycast routing sends users to the nearest healthy region.
  • Client IP : at Layer 7 the original IP is passed in X-Forwarded-For; at Layer 4 the PROXY protocol header carries it.
upstream app { least_conn; # algorithm: fewest active connections server 10.0.0.11:3000; server 10.0.0.12:3000; server 10.0.0.13:3000 backup; # used only if the others are down } server { listen 80; location / { proxy_pass http://app; } }

CDN & Edge Network

A Content Delivery Network (CDN) is a globally distributed network of servers that delivers content to users from a location geographically close to them instead of from the origin server. Each CDN location is called a Point of Presence (PoP) and contains edge servers that cache copies of content. When a user requests a file, DNS directs them to the nearest PoP, which serves the cached copy. This reduces latency, cuts load on the origin server, and absorbs traffic spikes and DDoS attacks. Examples: Cloudflare, Akamai, Fastly, Amazon CloudFront.

  • Caching : Edge servers store static assets (images, CSS, JavaScript, videos) based on cache headers like Cache-Control. On a cache miss, the edge fetches the file from the origin, serves it, and keeps a copy for the next visitor.
  • Cache Invalidation / Purge : When content changes, cached copies must be refreshed. This is done through TTL expiry, versioned file names (app.v2.js), or an explicit purge request to the CDN.
  • Reverse Proxy Model : A CDN works as a large distributed reverse proxy. The domain's DNS points at the CDN, all traffic enters through it, and the CDN forwards only what it cannot serve from cache to the origin.
  • Security Role : Because all traffic passes through it, a CDN commonly provides TLS termination, DDoS protection, a web application firewall (WAF), and bot filtering at the edge.
Edge Network & Edge Computing
  • Edge Network : The layer of servers closest to end users (the CDN's PoPs). "The edge" simply means computing that happens near the user rather than in a central data center.
  • Edge Computing / Edge Functions : Modern CDNs can run code at their edge locations, not just serve cached files. This is used for redirects, A/B testing, authentication checks, and personalization with very low latency. Examples: Cloudflare Workers, AWS Lambda@Edge, Vercel Edge Functions.
  • Application: A news site puts Cloudflare in front of its origin. Readers in India, Europe, and the US each load images and scripts from a nearby PoP, the origin only renders the articles, and a traffic spike on a breaking story is served almost entirely from cache.

  • Anycast : every PoP announces the same IP address, and internet routing delivers each user to the nearest one.
  • Origin Shield : an extra cache tier in front of the origin, so a cache miss at many PoPs becomes one request to the origin.
  • Security : never cache responses that contain Set-Cookie or personal data; misconfigured cache keys enable cache poisoning and web cache deception.

SSL/TLS

SSL (Secure Sockets Layer) and TLS (Transport Layer Security) are cryptographic protocols that provide secure communication over a computer network. They are commonly used to ensure data confidentiality, integrity, and authentication between clients (like web browsers) and servers (web servers, email servers, etc.).

  • Encryption: SSL/TLS use cryptographic techniques to encrypt data sent between the client and server. This ensures that even if intercepted, the data is unintelligible without the decryption keys.
  • Authentication: SSL/TLS protocols use digital certificates to authenticate the identity of parties involved in the communication. Certificates are issued by trusted Certificate Authorities (CAs) and verify that the server (and sometimes the client) is who they claim to be.
  • Integrity: SSL/TLS ensure data integrity by using cryptographic hashing algorithms. This prevents data from being altered or corrupted during transmission without detection.
  • TLS is the successor to SSL.
  • TLS has been designed with more robust security features and improvements based on the weaknesses found in SSL.
  • Versions : SSL 2.0/3.0 and TLS 1.0/1.1 are deprecated and insecure. TLS 1.2 and TLS 1.3 are current; TLS 1.3 (2018) is faster (one round trip to connect) and removes weak ciphers. The name "SSL certificate" survives, but those certificates are used with TLS.
  • Mutual TLS (mTLS) : The client also presents a certificate, so both sides authenticate each other. Common for service-to-service communication and zero trust networks.
Cipher Suites

A cipher suite names the algorithms a connection uses. TLS 1.3 allows only five AEAD suites and always uses ephemeral (EC)DHE key exchange; TLS 1.2 suites name every part.

TLS 1.2: TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256 | | | | | | | +-- PRF / hash | | +-------------- bulk cipher (AEAD) | +----------------------- certificate / authentication +----------------------------- key exchange (forward secrecy) TLS 1.3: TLS_AES_128_GCM_SHA256 | TLS_AES_256_GCM_SHA384 | TLS_CHACHA20_POLY1305_SHA256
  • Forward Secrecy : each session uses fresh ephemeral keys, so a server private key stolen later cannot decrypt past recorded traffic.
  • Certificate Chain : the server sends its leaf certificate plus intermediates; the client builds a path to a root CA in its trust store (see PKI in the Cyber Security cheatsheet).
  • SNI : the client sends the hostname in the ClientHello so a server hosting many sites can pick the right certificate. It is visible on the network unless Encrypted Client Hello (ECH) is used.
  • HSTS : Strict-Transport-Security: max-age=31536000; includeSubDomains; preload tells browsers to use HTTPS only, which blocks SSL-stripping attacks. Preloaded sites are hard-coded into browsers.
  • Certificate Transparency : every public certificate is recorded in public append-only logs, so mis-issued certificates can be spotted.
  • Post-Quantum Key Exchange : modern browsers and servers already use the hybrid X25519MLKEM768 group, which protects recorded traffic against future quantum computers.

Handshake

Handshake is a process of establishing communication between two devices or systems to ensure they are ready to exchange data. It involves the exchange of control messages to agree on connection parameters, protocols, or synchronization details.

Types of Handshakes
TCP Handshake (Three-Way Handshake)

The TCP handshake, or three-way handshake, is a process used in the TCP Protocol to establish a reliable connection between a client and a server before data is transmitted. It ensures both parties are synchronized and ready for communication.

  • SYN (Synchronize) : The client sends a SYN message to the server, requesting to establish a connection and specifying an initial sequence number.
  • SYN-ACK (Synchronize-Acknowledge) : The server responds with a SYN-ACK message, acknowledging the client's request and providing its own sequence number.
  • ACK (Acknowledge) : The client sends an ACK message back to the server, confirming receipt of the server's response. The connection is now established.
Client Server | ---- SYN (seq=x) ------------------> | | <--- SYN-ACK (seq=y, ack=x+1) ------- | | ---- ACK (ack=y+1) ----------------> | | connection established |
TCP Connection Termination (Four-Way Handshake)

Closing a TCP connection takes four steps because each side closes its direction independently: the client sends FIN, the server ACKs it, the server sends its own FIN when done, and the client ACKs that. The side that closed first then waits briefly in the TIME_WAIT state to catch delayed packets.

TLS/SSL Handshake

The TLS/SSL handshake is a process used to establish a secure, encrypted connection between a client (e.g., a web browser) and a server (e.g., a website). This handshake is a crucial part of the TLS (Transport Layer Security) or SSL (Secure Sockets Layer) protocols, which protect data in transit over a network.

TLS 1.3 Handshake (Simplified)
  • Client Hello : The client sends the TLS versions and cipher suites it supports, a random value, and its key share (a temporary public key).
  • Server Hello : The server picks the version and cipher suite and sends its own key share. Both sides can now compute the same session key (ECDHE key exchange) without ever sending it.
  • Certificate & Verify : The server sends its certificate and a signature proving it holds the matching private key, already encrypted.
  • Client Verification : The client checks the certificate chain against its trusted CAs and confirms the hostname matches.
  • Finished : Both sides confirm the handshake, and application data flows using fast symmetric encryption (e.g. AES-GCM).

TLS 1.2 needs two round trips before data can flow; TLS 1.3 needs one, and resumed sessions can send data immediately (0-RTT).

VPN

VPN, or Virtual Private Network, is a technique used to create a secure and encrypted connection over the internet between two or more devices or networks. VPN works by routing a device's internet connection through a secure, encrypted server that hides the IP address and location. VPNs use encryption and tunneling protocols to ensure that data transmitted over the internet is secure and protected from unauthorized access.

  • VPNs are commonly used in organizations to improve network security and enable remote access to network resources.
  • VPN is used for secure connections, privacy and anonymity (masking IP addresses), access, and bypassing censorship and restrictions.
Types of VPN
  • Remote Access VPN : Individual users connect securely to a company network from anywhere, such as employees working from home.
  • Site-to-Site VPN : Permanently connects two whole networks over the internet, such as a branch office and headquarters, usually configured between routers or firewalls.
  • Consumer VPN : Commercial services that route a user's traffic through the provider's servers for privacy or to appear in another country.
VPN Protocols
  • IPsec : A suite that secures traffic at the network layer, often paired with IKEv2. The standard for site-to-site VPNs.
  • OpenVPN : Open-source and widely supported, built on TLS, runs over UDP or TCP.
  • WireGuard : Modern, minimal, and fast, using modern cryptography with a very small codebase.
  • SSL/TLS VPN : Runs over port 443, so it passes through most firewalls; often used for browser-based remote access.
  • PPTP : Obsolete and insecure; should not be used.
IPsec Details
  • IKEv2 : negotiates keys and Security Associations (SAs) over UDP 500, or UDP 4500 when NAT is detected (NAT-T).
  • ESP (IP protocol 50) : encrypts and authenticates the payload; the normal choice.
  • AH (IP protocol 51) : authenticates only, with no encryption, and breaks through NAT; rarely used.
  • Tunnel Mode : encrypts the whole original packet inside a new one (site-to-site). Transport Mode : encrypts only the payload (host-to-host).
WireGuard Details
  • Runs over UDP (commonly port 51820) using the Noise protocol framework with Curve25519, ChaCha20-Poly1305, and BLAKE2s.
  • Peers are identified by public keys; AllowedIPs acts as both the routing table and the access list.
[Interface] PrivateKey = <client-private-key> Address = 10.8.0.2/32 DNS = 10.8.0.1 [Peer] PublicKey = <server-public-key> Endpoint = vpn.example.com:51820 AllowedIPs = 0.0.0.0/0, ::/0 # full tunnel; use 10.8.0.0/24 for split tunnel
  • Full vs Split Tunnel : a full tunnel sends all traffic through the VPN; a split tunnel sends only company traffic, leaving the rest on the local internet connection.
  • Kill Switch : blocks all traffic if the VPN drops, so nothing leaks outside the tunnel.
  • DNS Leaks : if DNS queries bypass the tunnel, the local network can still see every site visited.

Proxy

A proxy or proxy server acts as an intermediary between a client and the server. It forwards client requests to the destination server and returns the server's responses to the client. A proxy provides anonymity, content filtering, caching, and access control. Proxies can block or filter certain content based on predefined rules, policies, or access controls.

  • Proxies typically do not encrypt data between the client and the proxy server, so data transmitted beyond the proxy server may be vulnerable to interception.
  • An example of proxies are content delivery networks (CDNs), which use reverse proxies to distribute content closer to users, reducing latency and improving performance.
Types of Proxy
  • Forward Proxy : Sits in front of clients and makes requests on their behalf, so servers see the proxy's IP. Used for content filtering, caching, and anonymity, such as a corporate web proxy.
  • Reverse Proxy : Sits in front of servers and receives requests on their behalf, so clients never talk to the backend directly. Used for load balancing, TLS termination, caching, and protection. Examples: NGINX, Cloudflare.
  • Transparent Proxy : Intercepts traffic without any client configuration, often for filtering on school or ISP networks.
  • SOCKS Proxy : Forwards any TCP or UDP traffic (SOCKS5), not just web traffic, without understanding the application protocol.
Forward Proxy : Client -> [Proxy] -> Internet -> Server (hides the client) Reverse Proxy : Client -> Internet -> [Proxy] -> Servers (hides the servers)
Proxy vs VPN : A proxy forwards traffic for a specific application and usually does not encrypt it. A VPN encrypts all traffic from the device at the network level.
Proxy Chain
  • A proxy chain refers to a series of proxy servers or proxies that are linked together to route network traffic through multiple nodes in order to conceal the origin of the traffic or to bypass restrictions.
  • Each proxy in the chain forwards requests to the next, creating a chain of proxies through which data passes before reaching its destination.
  • It is used for bypassing restrictions, load balancing, and traffic management.
  • In some cases, proxy chains are used to distribute traffic across different servers or to optimize network performance by balancing the load.
Technical Details
  • Forward Proxy Requests : plain HTTP requests use the absolute URL: GET http://example.com/ HTTP/1.1. HTTPS uses a tunnel: CONNECT example.com:443, after which the proxy only relays encrypted bytes and sees the hostname but not the content.
  • TLS Interception : corporate proxies can decrypt HTTPS only by installing their own CA certificate on every device, then re-encrypting traffic with certificates they generate.
  • Forwarding Headers : reverse proxies pass the client details in X-Forwarded-For, X-Forwarded-Proto, X-Forwarded-Host, or the standard Forwarded header (RFC 7239). Trust them only from your own proxies, since clients can forge them.
  • Auto-Configuration : browsers can load a PAC file or discover one through WPAD; an attacker on the network who answers WPAD lookups can redirect traffic, so disable WPAD where it is unused.
  • SOCKS5 (RFC 1928) : relays any TCP traffic and UDP, supports authentication, and can resolve DNS at the proxy (socks5h) so lookups do not leak locally.

Firewall

A firewall is a network security system that monitors and controls incoming and outgoing network traffic based on predetermined security rules. It acts as a barrier between a trusted internal network and untrusted external networks, such as the internet. These rules can be configured to permit or deny traffic based on factors such as IP address, port number, protocol, or specific applications. Firewalls can be hardware devices, software programs, or a combination of both. Firewalls use a variety of techniques to control and monitor network traffic, including packet filtering, stateful inspection, and application-level filtering. It blocks unauthorized access and filters out malicious traffic.

Types of firewall
  • Network Firewall : A network firewall is a device that protects an entire network from unauthorized access and attacks. Network firewalls can be hardware or software based and are typically installed at the perimeter of a network to block unauthorized access from the internet.
  • Host-based Firewall : A host-based firewall is a firewall that protects an individual computer from unauthorized access and attacks. Host-based firewalls are typically software-based and are installed on individual computers to control access to network resources and block unauthorized traffic.
Firewall Techniques
  • Packet Filtering (Stateless) : Checks each packet's source and destination IP, port, and protocol against rules, independently of other packets. Fast, but has no context.
  • Stateful Inspection : Tracks active connections and only allows packets that belong to a legitimate, established connection.
  • Application-Level Gateway (Proxy Firewall) : Inspects traffic at Layer 7 and understands protocols like HTTP and FTP.
  • Next-Generation Firewall (NGFW) : Combines stateful inspection with deep packet inspection, application awareness, intrusion prevention (IPS), and user identity.
  • Web Application Firewall (WAF) : Protects web applications at the HTTP level from attacks like SQL injection and XSS.
Inbound vs Outbound Traffic

Firewall rules are written per direction. The direction is decided by who starts the connection, not by which way an individual packet travels.

  • Inbound (Ingress) : Connections started from outside toward your network or host, e.g. an internet user opening your website, or someone trying to SSH into your server.
  • Outbound (Egress) : Connections started from inside going out, e.g. your laptop browsing a website, a server downloading updates, or an app calling an external API.
  • Return Traffic : Replies to an outbound request travel back inward, but a stateful firewall recognizes them as part of an existing connection and allows them automatically. You do not need an inbound rule for websites you browse.

Filtering Best Practices
  • Default Deny Inbound : Block everything, then open only the ports a service actually needs (e.g. 443 on a web server), ideally only from known source IPs.
  • Egress Filtering : On servers and corporate networks, allow outbound traffic only to required destinations and ports (DNS, HTTPS, update servers). This limits malware command-and-control and data exfiltration if a host is compromised.
  • Anti-Spoofing (Ingress Filtering) : Drop packets arriving from the internet that claim an internal or private source IP (e.g. 10.0.0.0/8), since they must be forged.
  • Log Both Directions : Unexpected outbound connections are often the first sign of a compromised machine.

sudo ufw default deny incoming # block all inbound traffic by default sudo ufw default allow outgoing # allow all outbound traffic sudo ufw allow 22/tcp # allow inbound SSH sudo ufw allow 443/tcp # allow inbound HTTPS sudo ufw enable sudo ufw status verbose # Stricter egress for a server: deny outbound, then allow only what is needed sudo ufw default deny outgoing sudo ufw allow out 53 # DNS sudo ufw allow out 443/tcp # HTTPS (updates, APIs)

  • Connection Tracking : states NEW, ESTABLISHED, RELATED (e.g. an ICMP error for an existing flow), and INVALID; allowing ESTABLISHED,RELATED is what makes the firewall stateful.

Defense in Depth

Defense in Depth (DiD) is a security strategy that protects a network with multiple independent layers of controls, so that if one layer fails or is bypassed, the next one still stops or slows the attacker. The idea comes from military strategy: no single wall is trusted to hold. It assumes that any one control can fail, and that a breach is always possible.

Security Layers
Layer Example Controls
Policies, Procedures & People security policies, awareness training, incident response plans
Physical locked server rooms, badge access, CCTV
Perimeter edge firewall, DDoS protection, VPN gateway, email filtering
Internal Network segmentation (VLANs, subnets), internal firewalls, IDS/IPS, NAC
Host / Endpoint host firewall, antivirus/EDR, patching, hardening
Application WAF, secure coding, authentication and MFA, input validation
Data encryption at rest and in transit (TLS), access control, backups, DLP
Monitoring (across all layers) logging, SIEM, alerting, regular audits
Layered Network Design

A common DiD network places public-facing servers in a DMZ (Demilitarized Zone, also called a screened subnet). The DMZ is a separate network segment between the internet and the internal LAN, so a compromised public server still cannot reach internal systems directly.

Internet | [ Edge Firewall + DDoS protection ] only 80/443 allowed inbound | DMZ : web server, reverse proxy, mail relay | [ Internal Firewall ] DMZ may reach only the app servers it needs | Internal LAN : VLAN 10 Users | VLAN 20 App servers | VLAN 99 Management | Data tier : databases, reachable only from the app servers
Key Principles
  • Least Privilege : Every user, device, and service gets only the access it needs.
  • Segmentation : Split the network into zones (DMZ, users, servers, management) with firewall rules between them, limiting how far an attacker can move. Micro-segmentation applies the same idea down to individual workloads.
  • Default Deny : Block traffic unless it is explicitly allowed, both inbound and outbound (see Firewall).
  • Diversity of Controls : Different kinds of controls (or vendors) at different layers, so one bypass technique does not defeat them all.
  • Visibility : Log and monitor at every layer; a layer that does not alert only delays an attacker without anyone noticing.
  • Redundancy : No single point of failure for critical controls.
Example: Layers Stopping One Attack
  1. Email Filter : blocks most malicious attachments before they reach users.
  2. Awareness Training : the user recognizes and reports a message that slipped through.
  3. Endpoint Protection : EDR blocks the payload if the file is opened anyway.
  4. Segmentation : even if one PC is compromised, it cannot reach the database VLAN.
  5. Egress Filtering : the compromised PC cannot connect to unknown external servers.
  6. Monitoring : the blocked outbound attempt raises a SIEM alert, and the SOC isolates the PC.
Defense in Depth vs Zero Trust : They work together. DiD adds many layers of protection; Zero Trust removes implicit trust inside the network by verifying every user, device, and request, so being "inside the perimeter" grants nothing by itself.

TOR

TOR stands for The Onion Router, a free, open-source software that enables anonymous communication over the internet. It is designed to protect users' privacy and security by routing internet traffic through a series of volunteer-operated servers, known as nodes or relays, that encrypt and re-encrypt the data multiple times, making it very difficult to trace back to the original user.

  • Onion routing is the technology behind the TOR (The Onion Router) network, and it is designed to provide anonymous communication over the internet.
  • It works by encrypting data in multiple layers, similar to the layers of an onion, and then routing it through a network of servers (nodes) to ensure that the origin, destination, and contents of the communication are hidden from potential eavesdroppers.
  • This process helps to obscure users' IP addresses, making it difficult for anyone to track their online activities or locate them.
Dark Web

The dark web is a part of the deep web (the portion of the internet not indexed by search engines) that is intentionally hidden and requires special tools, such as TOR, to access. Websites on the dark web have ".onion" domains, which are only accessible via the Tor browser. These sites are typically not indexed by search engines, providing a higher level of anonymity and privacy. The dark web is known for hosting both legal and illegal content. However, it is also used by individuals seeking privacy, engaging in political activism, practicing journalism, or escaping censorship in authoritarian regimes.

How a Circuit Works
You -> [Guard relay] -> [Middle relay] -> [Exit relay] -> example.com knows your IP knows neither knows the destination not destination you nor dest not your IP
  • Onion Encryption : the client wraps each message in three layers of encryption, one per relay; each relay removes only its own layer, so no single relay knows both ends.
  • Circuits : built through three relays chosen from the consensus published by directory authorities, and rotated for new destinations roughly every 10 minutes.
  • Onion Services : .onion sites (v3 addresses are 56 characters, derived from an Ed25519 public key) are reached without an exit relay, so traffic stays inside Tor end to end.
  • Bridges & Pluggable Transports : unlisted entry relays and traffic disguises (obfs4, Snowflake) help users in countries that block Tor.
  • Limitations : the exit relay sees unencrypted traffic (always use HTTPS), an adversary watching both ends can correlate timing, and browser fingerprinting can identify users (use Tor Browser, not a normal browser through Tor).
