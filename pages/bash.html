Shell & Bash

A shell is a program that takes commands from the user and asks the operating system's kernel to run them. It is both an interactive command interpreter and a scripting language. Bash (Bourne Again SHell) is the GNU project's shell, written by Brian Fox in 1989 as a free replacement for the original Bourne shell (sh). It is the default shell on most Linux distributions and is also available on macOS and Windows (Git Bash, WSL).

User  -->  Terminal  -->  Shell (Bash)  -->  Kernel  -->  Hardware
  • Terminal (Emulator) : The window that displays text and sends your keystrokes, e.g. GNOME Terminal, Konsole, Windows Terminal.
  • Shell : The program running inside the terminal that interprets what you type.
  • Console : Historically the physical terminal attached to a machine; today often used to mean any text interface.
Types of Shells -
Shell Description
sh Bourne shell (1979), the original UNIX shell. Today /bin/sh is a POSIX-compatible shell (often dash or bash).
bash Bourne Again Shell. Default on most Linux distros; adds arrays, [[ ]], history and more on top of sh.
dash Small, fast POSIX shell. Used as /bin/sh on Debian and Ubuntu for running system scripts.
zsh Z shell. Bash-compatible with richer completion and themes (Oh My Zsh). Default on macOS since Catalina.
fish Friendly interactive shell with autosuggestions out of the box. Not POSIX-compatible.
ksh KornShell. Common on commercial UNIX systems (AIX, Solaris).
csh / tcsh C shell, with C-like syntax. Used on some BSD systems. 
echo $SHELL          # your default login shell
echo $0              # the shell running right now
echo $BASH_VERSION   # Bash version
cat /etc/shells      # shells installed on the system
chsh -s /bin/zsh     # change your default shell
Types of Shell Sessions -
  • Interactive Shell : Reads commands typed by a user at a prompt.
  • Non-Interactive Shell : Runs a script; no prompt, no user input.
  • Login Shell : The first shell after logging in (console, SSH). Reads /etc/profile, then ~/.bash_profile (or ~/.profile).
  • Non-Login Shell : A shell opened from an existing session, such as a new terminal tab. Reads ~/.bashrc.
Startup Files -
  • ~/.bashrc : Aliases, functions, prompt, and shell options for interactive shells. Most customization goes here.
  • ~/.bash_profile / ~/.profile : Environment variables for login shells. Usually also sources ~/.bashrc.
  • ~/.bash_history : Saved command history.
  • ~/.bash_logout : Runs when a login shell exits.
source ~/.bashrc     # reload after editing (same as: . ~/.bashrc)

Bash Scripts

A Bash script is a plain text file that contains a series of commands that are executed in sequence. Scripts usually have a .sh extension (for example: script.sh). The first line is the shebang (#!), which tells the system which interpreter should run the script.

  • #!/bin/bash : run with Bash.
  • #!/usr/bin/env bash : find Bash on the user's PATH; more portable across systems.
  • #!/bin/sh : run with a POSIX shell; avoid Bash-only features like arrays and [[ ]].
Ex :
#!/bin/bash

mkdir Docs
cp doc1.txt Docs/
rm doc1.txt
clear
• Executing Scripts :
chmod +x [script]    # give execute permission (needed for ./ only)
./[script]           # run using the shebang interpreter
bash [script]        # run with bash explicitly (no execute permission needed)
sh [script]          # run with the POSIX shell
source [script]      # run inside the current shell
Ex :
chmod +x script.sh
./script.sh
bash script.sh
• Script Template :
#!/usr/bin/env bash
set -euo pipefail            # exit on error, unset variable, or failed pipe

# Usage: ./backup.sh <source-dir>
src="${1:?Usage: $0 <source-dir>}"
dest="/tmp/backup-$(date +%F).tar.gz"

main() {
    echo "Backing up $src to $dest"
    tar -czf "$dest" "$src"
    echo "Done"
}

main "$@"

Variables

Variables are untyped strings by default. There must be no spaces around =. Names can contain letters, digits and underscores, and cannot start with a digit.

Declaring :
greet="Hello World"
num=17
greet = "Hello"      # wrong: runs a command named "greet"
Access :
echo $greet
echo "Number is ${num}"
echo "${num}th place"    # braces separate the name from following text
Read-Only Variable :
readonly COUNT=1
Declare Integer :
declare -i num=10
num=num+5            # arithmetic is applied: num is 15
Remove Variable :
unset num
• Environment Variables :

Normal variables exist only in the current shell. export makes a variable an environment variable, so child processes and scripts started from the shell can see it.

export API_URL="https://api.example.com"
export PATH="$PATH:$HOME/bin"     # add a folder to PATH
env                               # list environment variables
printenv HOME                     # print one variable
API_KEY=abc ./script.sh           # set a variable for one command only
Variable Description
$HOME home directory of current user
$USER current username
$PATH colon-separated list of directories searched for commands
$PWD / $OLDPWD current / previous working directory
$SHELL path of the default login shell
$HOSTNAME name of the machine
$PS1 format of the shell prompt
$RANDOM random integer between 0 and 32767
$SECONDS seconds since the shell (or script) started
$IFS Internal Field Separator used for word splitting (default: space, tab, newline)

Quoting

Quoting controls which special characters Bash interprets. Unquoted variables are split on spaces and expanded as wildcards, which is a common source of bugs.

  • Double Quotes "..." : Expands variables, $( ) and \ escapes, but prevents word splitting and globbing.
  • Single Quotes '...' : Everything is literal; nothing is expanded.
  • Backslash \ : Escapes the next single character.
  • ANSI-C Quotes $'...' : Interprets escapes like \n and \t.
name="World"
echo "Hello $name"       # Hello World
echo 'Hello $name'       # Hello $name
echo "Price: \$5"        # Price: $5
echo $'Line1\nLine2'     # two lines

file="my report.txt"
cat $file                # wrong: cat sees two files "my" and "report.txt"
cat "$file"              # right
Rule of thumb : Always double-quote variable expansions ("$var", "$@") unless you specifically want word splitting.

Strings

Declaring :
greet="Hello World"
Access :
echo "$greet"
Concatenation :
first="Hello"; second="World"
echo "$first $second"
first+=" there"          # append
Length of string :
echo ${#greet}           # 11
Substring :
echo ${greet:0:5}        # Hello   (offset 0, length 5)
echo ${greet:6}          # World   (from offset 6)
echo ${greet: -5}        # World   (last 5 chars; space before - is required)
String Replace :
greet="Hello World World"
echo ${greet/World/Universe}     # replace first match:  Hello Universe World
echo ${greet//World/Universe}    # replace all matches:  Hello Universe Universe
Remove Prefix / Suffix :
file="archive.tar.gz"
echo ${file#*.}          # tar.gz    (remove shortest match from start)
echo ${file##*.}         # gz        (remove longest match from start)
echo ${file%.*}          # archive.tar  (remove shortest match from end)
echo ${file%%.*}         # archive   (remove longest match from end)

path="/home/user/docs/notes.txt"
echo ${path##*/}         # notes.txt  (like basename)
echo ${path%/*}          # /home/user/docs  (like dirname)
Change Case :
name="hello World"
echo ${name^^}           # HELLO WORLD
echo ${name,,}           # hello world
echo ${name^}            # Hello World (first character)

Arrays

Declaring Indexed Array :
fruits=("apple" "mango" "banana" "orange")
declare -a fruits=("apple" "mango")      # explicit form
Declaring Associative Array :

Key-value arrays (Bash 4+) must be declared with declare -A. Elements are separated by spaces, not commas.

declare -A capital=(["India"]="New Delhi" ["Nepal"]="Kathmandu" ["Bhutan"]="Thimphu")

declare -A india
india["capital"]="New Delhi"
Indexing :
fruits[0]="grapes"
Access Element :
echo ${fruits[0]}
echo ${fruits[-1]}       # last element
echo ${capital["India"]}
Print All Elements :
echo "${fruits[@]}"
Print Keys / Indexes :
echo "${!capital[@]}"     # India Nepal Bhutan (order not guaranteed)
echo "${!fruits[@]}"      # 0 1 2 3
Length of Array :
echo ${#fruits[@]}
Append, Slice & Remove :
fruits+=("kiwi")             # append
echo "${fruits[@]:1:2}"      # slice: 2 elements starting at index 1
unset 'fruits[1]'            # remove one element
unset fruits                 # delete the whole array
Input :
read -a fruits

Input

Input (STDIN) :
read [var]
read -r [var]        # recommended: -r keeps backslashes literal
Prompt Input :
read -p "Username : " [var]
Secure Prompt Input :
read -sp "Password : " [var]     # -s hides what is typed
Input NChar :
read -n [x] [var]                # stop after x characters
Input with Timeout :
read -t 5 -p "Continue? " answer || echo "Timed out"
Array Input :
read -a [array]
Split Input into Variables :
read -r first last <<< "Linus Torvalds"
echo "$last"                     # Torvalds

IFS=: read -r user _ uid _ <<< "root:x:0:0"
echo "$user has UID $uid"        # root has UID 0

Output

Print (STDOUT) :

The echo prints output followed by a new line character.

echo "Hello World"

msg="Hello World"
echo "$msg"
echo "Hii, ${msg}"
echo -n "No newline"
Enable Backslash Escapes :
echo -e "\n Hello World"
Special Char in Output :
echo '$Hello World'
Formatted Print (STDOUT) :

The printf prints output in the specified format; it does not append an implied newline. It behaves the same on every system, so prefer it over echo -e in scripts.

printf "\n%s\n\n" "Hello World"
printf "%-10s %5d\n" "Apples" 42      # left-align text in 10 chars, number in 5
printf "%.2f\n" 3.14159               # 3.14
printf "%05d\n" 42                    # 00042

Format specifiers: %s string, %d integer, %f float, %x hex, %% literal percent.

• Logical Operator :
Operator Operation

The older -o (or) and -a (and) inside [ ] still work but are deprecated because they are ambiguous.

• Relational Operator :

(Numerical Comparison)

Operator Operation
[expr] -eq [expr] equal
[expr] -ne [expr] not equal
[expr] -gt [expr] greater than
[expr] -lt [expr] less than
[expr] -ge [expr] greater than or equal
[expr] -le [expr] less than or equal
Ex :
if [ 80 -gt 40 ]
then
    echo "Greater"
fi

if (( 80 > 40 )); then echo "Greater"; fi    # arithmetic form
• Relational Operator :

(String Comparison)

Operator Operation
[string] = [string] equal
[string] != [string] not equal
[string] == [pattern] equal; inside [[ ]] the right side can be a wildcard pattern
[string] =~ [regex] regex match (only inside [[ ]]); groups are saved in BASH_REMATCH
-n [string] true if length of string is nonzero
-z [string] true if length of string is zero
Ex :
if [ "Hello" = "Hi" ]
then
    echo "Matched"
else
    echo "Not Matched"

[[ $file == *.pdf ]] && echo "PDF file"
[[ "2026-10-19" =~ ^([0-9]{4})- ]] && echo "Year: ${BASH_REMATCH[1]}"
• Lexicographic Comparison :
Operator Operation
[[ [string] > [string] ]] true if left string sorts after right string
[[ [string] < [string] ]] true if left string sorts before right string

Inside single brackets [ ], > and < are redirections and must be escaped as \> and \<.

• File Testing Operator :
Operator Operation
-e [file] true if file exists
-f [file] true if file exists and is regular file
-d [file] true if file exists and is directory
-L [file] true if file exists and is symbolic link
-c [file] true if file exists and is character device
-b [file] true if file exists and is block device
-r [file] true if file exists and read permission is granted
-w [file] true if file exists and write permission is granted
-x [file] true if file exists and execute permission is granted
-s [file] true if size of file is greater than zero
[file1] -nt [file2] true if file1 is newer than file2 (-ot for older)
Ex :
if [ -f text.txt ]
then
    echo "text.txt exists and it is regular file."
fi
• Test Syntax :
  • [ ] (test) : POSIX, works in every shell. Quote variables, and give spaces between the brackets, operands and operator.
  • [[ ]] : Bash keyword with safer parsing: no word splitting, supports &&, ||, == patterns and =~ regex. Preferred in Bash scripts.
  • (( )) : Arithmetic evaluation with C-style operators (>, <=, ==); true when the result is non-zero.
  • Grouping : Use \( \) inside [ ], or plain ( ) inside [[ ]].

Arithmetic

Bash only does integer arithmetic. Use $(( )) for calculations, (( )) for conditions and updates, and bc or awk for decimals.

a=10; b=3
echo $(( a + b ))        # 13   ($ inside is optional)
echo $(( a / b ))        # 3    (integer division)
echo $(( a % b ))        # 1
echo $(( 2 ** 10 ))      # 1024
(( a++ ))                # increment in place
(( a > b )) && echo "a is bigger"
let "c = a * b"          # older alternative
echo "scale=2; 10 / 3" | bc     # 3.33  (decimals with bc)
• Expr :

Expr is an external command that evaluates an expression and prints the result. It is the old way to do math in shell scripts; prefer $(( )) in new code. Special characters like * and < must be escaped.

Syntax :
expr [OPTION] [EXPRESSION]
Ex :
# Example 1:
expr 1 + 2
expr 5 - 3
expr 2 \* 3
expr 8 / 2

# Example 2:
read x
read y
sum=$(expr $x + $y)
echo "Sum = $sum"

# Example 3: comparing numbers with '=' (prints 1 if true, 0 if false)
res=$(expr $x = $y)
echo $res

# Example 4: prints 1 when x < y
res=$(expr $x \< $y)
echo $res

# Example 5: length of string (GNU expr)
x="Hello World"
echo $(expr length "$x")         # 11

# Example 6: extract substring: 3 characters starting at position 2
x="Hello World"
sub=$(expr substr "$x" 2 3)
echo $sub                        # ell

# Example 7: position of first character found from a set
x="Hello World"
c=$(expr index "$x" "o")
echo $c                          # 5

Parameter Expansion

Default values and checks for variables that may be unset or empty. String operations like ${var#prefix} are listed under Strings.

Var Description
${x} substitute value of variable x
${x:-y} if x is unset or empty, use y instead (x does not change)
${x:=y} if x is unset or empty, set x to y and use it
${x:+y} if x is set and not empty, use y; otherwise use nothing (x does not change)
${x:?msg} if x is unset or empty, print msg to standard error and exit the script
${!x} indirect expansion: value of the variable whose name is stored in x
Ex :
port="${PORT:-8080}"                 # use $PORT, or 8080 if not set
: "${LOG_DIR:=/var/log/myapp}"       # set a default once
db="${DB_HOST:?DB_HOST is required}" # fail fast if missing

Command Substitution

Command substitution replaces a command with its output. The backquote form is old-style; the $( ) form is recommended because it is easier to read and can be nested.

• Dollar Sign & Parenthesis :
Syntax :
$([command])
Ex :
# Example 1:
echo "Today is $(date)"

# Example 2: nesting
echo "Script folder: $(basename "$(pwd)")"

# Example 3: store output in a variable
count=$(ls | wc -l)
echo "Files: $count"
• Back-Quote :
Syntax :
`[command]`
Ex :
DATE=`date`
echo "Date is $DATE"

USERS=`who | wc -l`
echo "Logged in users are $USERS"
• Process Substitution :

<( ) makes a command's output look like a file, for commands that need file names.

diff <(sort a.txt) <(sort b.txt)

Syntax :
if [ condition ]

    #Statement

    #Statement

    #Statement

Loops

• While Loop :
Syntax :
while [ condition ]
do
    #Statement
done
Ex :
# Example 1: print "Hello World" 5 times
count=0
while [ $count -lt 5 ]
do
    echo "Hello World"
    count=$((count+1))
done

# OR
count=0
while (( count < 5 ))
do
    echo "Hello World"
    ((count++))
done

# Example 2: read a file line by line (safest form)
while IFS= read -r line
do
    echo "$line"
done < file.txt

# Example 3: infinite loop
while true
do
    echo "Infinite Loop..."
done

# Example 4: infinite loop (":" always succeeds)
while :
do
    echo "Infinite Loop..."
done

# Example 5: factorial - pass number as command argument
counter=$1
factorial=1
while [ $counter -gt 0 ]
do
    factorial=$(( factorial * counter ))
    counter=$(( counter - 1 ))
done
echo $factorial
• For Loop :
Syntax :
for [var] in [list]
do
    #Statement
done
2nd Syntax (C-style) :
for (( init; condition; update ))
do
    #Statement
done
Ex :
# Example 1: input array & print
read -a array
count=1
for i in "${array[@]}"
do
    echo "Element $count : $i"
    ((count++))
done

# Example 2:
for i in 1 2 3 4 5
do
    echo $i
done

# Example 3:
for i in {1..25}
do
    echo $i
done

# Example 4: increment by 2 from 0 to 10
for i in {0..10..2}
do
    echo $i
done

# OR using seq - increment by 2 from 0 to 10
for i in $(seq 0 2 10)
do
    echo $i
done

# Example 5:
for (( i=1; i<=5; i++ ))
do
    echo $i
done

# Example 6: infinite loop
for (( ; ; ))
do
    echo "Infinite Loop..."
done

# Example 7: create 10 copies of test.txt
for i in $(seq 1 10)
do
    cp test.txt "test_${i}.txt"
done

# OR single line format
for i in {1..10}; do cp test.txt "test_${i}.txt"; done

# Example 8: loop over files (no ls needed)
for file in *.log; do
    echo "Processing $file"
done

# Example 9: iterating associative array
for key in "${!capital[@]}"; do
    echo "$key : ${capital[$key]}"
done
• Until Loop :

Executes until the condition becomes true (runs while it is false).

Syntax :
until [ condition ]
do
    #Statement
done
Ex :
count=5
until [ $count -le 0 ]
do
    echo "count = $count"
    count=$((count-1))
    sleep 1
done
• Select Loop :

Builds a numbered menu and reads the user's choice.

Syntax :
select [var] in [list]
do
    #Statements
done
Ex :

        ;;
    orange|apple)
        echo "Go to fruit market"
        ;;
    none)
        break
        ;;
    *)
        echo "ERROR: Invalid Selection"
        ;;
    esac
done
• Loop Controls :
1. Break Statement -
a=1
while [ $a -lt 10 ]
do
    echo $a
    if [ $a -eq 5 ]
    then
        break
    fi
    a=$((a + 1))
done
2. Continue Statement -
for num in 1 2 3 4 5 6 7
do
    if (( num % 2 == 0 ))
    then
        echo "Even"
        continue
    fi
    echo $num
done

Functions

Syntax :
name() {
    #Statements
}

# alternative Bash syntax
function name {
    #Statements
}
Calling Function :
greet() {
    echo "Hello World"
}

greet
Function with Parameter :

Arguments are accessed with $1, $2, ..., $@, just like script arguments.

greet() {
    echo "Hello $1"
}

greet World
Call within statement :
capital() {
    echo "$1" | tr 'a-z' 'A-Z'
}

name="admin"
echo "Capital: $(capital "$name")"
Return Values :

return only sets an exit status (0-255), not data. To return data, echo it and capture it with $( ).

is_even() {
    (( $1 % 2 == 0 ))        # exit status of the last command is returned
}

add() {
    echo $(( $1 + $2 ))
}

is_even 4 && echo "4 is even"
sum=$(add 3 5)
echo "Sum = $sum"
Local Variables :

Local variables are defined within a function and have local scope. They are only accessible within the function where they are defined, not outside of it. They are declared with the local keyword. Variables without local are global.

swap() {
    local t=$a
    a=$b
    b=$t
}

a=3
b=7
printf "a = %s, b = %s\n" "$a" "$b"
swap
printf "a = %s, b = %s\n" "$a" "$b"

Command Line Arguments

Also called positional parameters or special parameters.

Arguments Description
$0 name (path) of the script
basename $0 filename of script without leading path
$1 ... $9, ${10} arguments passed to script/function (braces needed from 10 onward)
$# total number of arguments passed
"$@" all arguments as separate words; use this to pass arguments on safely
"$*" all arguments joined into a single string
$? exit status of last command (0 for success, non-zero for failure)
$$ PID of current shell
$! PID of last background process
$_ last argument of the previous command
$- current shell option flags
Ex :
# ./args.sh apple banana "green grape"
echo "Script: $0"
echo "Count: $#"           # 3
for arg in "$@"; do
    echo "- $arg"          # prints "green grape" as one item
done

shift                      # drop $1; $2 becomes $1
echo "First now: $1"       # banana
• Parsing Options with getopts :
# ./deploy.sh -v -e prod
verbose=false
env="dev"
while getopts "ve:h" opt; do
    case $opt in
        v) verbose=true ;;
        e) env="$OPTARG" ;;      # option that takes a value (e:)
        h) echo "Usage: $0 [-v] [-e env]"; exit 0 ;;
        *) exit 1 ;;
    esac
done
shift $((OPTIND - 1))           # remaining non-option arguments
echo "env=$env verbose=$verbose"

Redirection

Every process starts with three standard streams, identified by file descriptors.

File Descriptor Value
STDIN (standard input) 0
STDOUT (standard output) 1
STDERR (standard error) 2
• Output Redirection :
Commands Description
[command] > [file] redirect STDOUT to file (overwrite)
[command] 1> [file] redirect STDOUT to file (1 is the default descriptor)
[command] >> [file] redirect and append STDOUT to file
[command] 2> [file] redirect STDERR (standard error) to file
[command] &> [file] redirect STDOUT and STDERR to file
[command] > [file] 2>&1 redirect STDOUT and STDERR to file (POSIX form; order matters)
[command] > /dev/null redirect STDOUT to null (discard STDOUT)
[command] &> /dev/null discard STDOUT and STDERR
> [file] create empty file (or empty an existing one)
cat > [file] type text into a file (Ctrl + D to finish)
• Input Redirection :
Commands Description
[command] < [file] read STDIN from a file
[command] <<< "[text]" here-string: pass a string as STDIN
[command] << EOF here-document: pass multiple lines as STDIN until the line EOF
Ex :
wc -l < access.log                 # count lines from a file
tr 'a-z' 'A-Z' <<< "hello"          # HELLO

cat << EOF > config.ini              # write a multi-line file
[server]
host=$HOSTNAME
port=8080
EOF

cat << 'EOF'                        # quoted 'EOF': no variable expansion
Price is $5
EOF
• Custom File Descriptor :

Define your own file descriptor (3 to 9) and redirect to it.

  1. Open file descriptor x for reading and writing a file : exec x<> [file]
  2. Redirect to it : [command] >&x
  3. Close file descriptor x : exec x>&-
Ex :
$ exec 3<> log.txt
$ echo "Hello" >&3     # output is redirected to log.txt
$ cat log.txt
Hello

$ exec 3>&-

Piping

Pipelines or pipes (|) connect the STDOUT of one command to the STDIN of the next. Each command in a pipeline runs at the same time, in its own process.

Syntax :
[command] | [command]
[command] |& [command]     # pipe STDOUT and STDERR
Ex :
# Output 1 page at time:
ls -lR | less

# Display 10 newest files:
ls -t | head -10

# Print lines with word "Hello" in file.txt:
grep Hello file.txt

# Sort names of files containing the word "index":
grep -l index * | sort

# Save output to a file AND show it on screen:
ls -l | tee listing.txt

# Turn input lines into arguments for another command:
find . -name "*.tmp" | xargs rm
  • Exit Status : By default a pipeline's exit status is that of the last command. With set -o pipefail, it fails if any command fails.
  • PIPESTATUS : The array ${PIPESTATUS[@]} holds the exit status of every command in the last pipeline.

Job Control

Bash can run commands in the background and move them between background and foreground.

Commands Description
[command] & run command in the background
jobs list background and stopped jobs
Ctrl + Z suspend the foreground job
bg %[n] resume job n in the background
fg %[n] bring job n to the foreground
kill %[n] terminate job n
wait wait for all background jobs to finish
nohup [command] & keep running after the terminal closes (output goes to nohup.out)
disown %[n] detach a running job from the shell
Ex :
# run two downloads in parallel, then continue
curl -sO https://example.com/a.zip &
curl -sO https://example.com/b.zip &
wait
echo "Both downloads finished"

Bash Aliases

An alias is a short name that is replaced by a longer command. Aliases cannot take arguments in the middle of the command; use a function for that.

Syntax :
alias name='[command]'
alias                  # list all aliases
unalias name           # remove an alias
\ls                    # run the original command, bypassing an alias

Save aliases in the file ~/.bashrc so they load in every new shell, then reload it with -

source ~/.bashrc
Ex :
alias ll='ls -alF'
alias gs='git status'
alias update='sudo apt update && sudo apt upgrade'

# needs an argument, so use a function instead of an alias:
cpp() { g++ "$1" -o /tmp/a.out && /tmp/a.out; }

Brace Expansion

Generates lists of strings before the command runs. It happens before variable expansion, so {1..$n} does not work; use seq or a C-style loop instead.

  • echo {1,2,3} : 1 2 3
  • echo {1..5} : 1 2 3 4 5
  • echo {5..1} : 5 4 3 2 1
  • echo {1..-3} : 1 0 -1 -2 -3
  • echo {1..10..2} : 1 3 5 7 9
  • echo {01..05} : 01 02 03 04 05
  • echo {A..E} : A B C D E
  • echo {A..H..2} : A C E G
  • echo a{2..5}b : a2b a3b a4b a5b
  • echo {code1,code2,code3}.c : code1.c code2.c code3.c
  • echo code{.c,.cpp,.py,.sh} : code.c code.cpp code.py code.sh
  • mkdir -p project/{src,tests,docs} : creates three folders at once
  • cp config.yml{,.bak} : copies config.yml to config.yml.bak

Globbing

Globbing (wildcards) is how Bash matches file names. It is not the same as regular expressions: in a glob, * means "any characters", while in regex it means "repeat the previous item". For regex with grep, see the Linux cheatsheet.

Pattern Matches
* any number of characters (including none)
? exactly one character
[abc] one character from the set
[a-z] one character from the range
[!abc] or [^abc] one character not in the set
** any files and folders recursively (needs shopt -s globstar)
Ex :
  • ls file[1-9] : files named file1 to file9
  • ls *[0-9]* : files whose names contain a digit (file1.txt test2.sh note5.pdf)
  • ls test.* : files named "test" with any extension (test.txt test.pdf)
  • ls ab* : files starting with "ab" (ab.txt abcd abort.sh)
  • ls *.{pdf,doc,exe} : files ending with .pdf, .doc or .exe
  • ls a[a-d]b : aab abb acb adb
  • ls test_[!3] : test_1 test_2 test_4 (any single character except 3)
  • ls ???.txt : files with exactly three characters before .txt
Glob Options (shopt) -
  • shopt -s nullglob : a pattern with no matches expands to nothing instead of itself.
  • shopt -s dotglob : * also matches hidden files.
  • shopt -s globstar : enables **, e.g. ls **/*.js.
  • shopt -s extglob : extended patterns such as !(*.log) (everything except .log files).

Eval

Eval joins its arguments into one string and runs it as a command. It is powerful but dangerous with untrusted input, because any text in the variable is executed as code.

Syntax :
eval [arg...]
Ex :
list="ls | more"
eval $list           # the | is treated as a real pipe

$list                # without eval: ls gets "|" and "more" as file names

Exit Codes & Error Handling

Every command returns an exit status: 0 means success and anything from 1 to 255 means failure. if, && and || all work on exit statuses.

Code Meaning
0 success
1 general error
2 misuse of a shell builtin (e.g. wrong syntax)
126 command found but not executable (permission problem)
127 command not found
128 + n killed by signal n (e.g. 130 = Ctrl + C, 137 = kill -9)
• Strict Mode :
set -e            # exit immediately if a command fails
set -u            # treat unset variables as an error
set -o pipefail   # a pipeline fails if any command in it fails
set -euo pipefail # all three together (common at the top of scripts)
• Handling Errors :
cd /some/dir || { echo "Cannot cd" >&2; exit 1; }

if ! grep -q "ERROR" app.log; then
    echo "No errors found"
fi

die() { echo "Error: $*" >&2; exit 1; }
[ -f config.ini ] || die "config.ini missing"
• Trap :

trap runs a command when the script exits or receives a signal, which is ideal for cleanup.

tmp=$(mktemp)
trap 'rm -f "$tmp"' EXIT                    # always delete the temp file
trap 'echo "Interrupted"; exit 130' INT     # handle Ctrl + C
trap 'echo "Failed at line $LINENO"' ERR    # report the failing line

Debugging

bash -n script.sh      # check syntax without running
bash -x script.sh      # print each command (with expanded values) before running it
bash -v script.sh      # print each line as it is read

set -x                 # turn tracing on inside a script
set +x                 # turn it off again
PS4='+ ${LINENO}: '    # show line numbers in -x output
  • ShellCheck : A static analysis tool (shellcheck script.sh) that finds bugs such as missing quotes, unused variables and wrong test syntax. Strongly recommended for every script.
  • Print Debug Info to STDERR : echo "debug: $var" >&2 keeps debug messages out of the script's real output.
