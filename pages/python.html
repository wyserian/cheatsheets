Python

Python is a dynamically and strongly typed, interpreted, multi-paradigm language created by Guido van Rossum (first released 1991). Its design favors readability: blocks are defined by indentation. It is widely used for scripting, automation, web back ends, data science, machine learning, and security tooling.

  • CPython : the reference implementation. Source is compiled to bytecode (cached in __pycache__/*.pyc) and executed by a stack-based virtual machine. Other implementations: PyPy (JIT), MicroPython.
  • Memory : reference counting plus a cyclic garbage collector.
  • GIL : the Global Interpreter Lock lets only one thread run Python bytecode at a time, so threads help with I/O but not CPU-bound work. Python 3.13 added an optional free-threaded build (officially supported from 3.14).
  • Versions : Python 2 reached end of life in 2020. A new 3.x release ships every October with five years of support.
  • PEPs : Python Enhancement Proposals define the language; PEP 8 is the style guide.

  • Tools : uv (fast installer and project manager), Poetry, pipx (global CLI tools), Ruff (linter and formatter), mypy / Pyright (type checkers), pytest (tests).

Functions

def greet(name: str, greeting: str = "Hello") -> str: """Return a greeting.""" # docstring, shown by help() return f"{greeting}, {name}" greet("Ada"); greet(greeting="Hi", name="Ada") def log(*args, **kwargs): ... # extra positional args (tuple) and keyword args (dict) def f(a, b, /, c, *, d): ... # a, b positional-only; d keyword-only log(*items, **options) # unpack into arguments square = lambda x: x * x # small anonymous function sorted(users, key=lambda u: u.age)
  • Scope (LEGB) : names are looked up in Local, Enclosing, Global, then Built-in scope. Use global or nonlocal to assign to an outer name.
  • Closures : nested functions keep access to the enclosing function's variables.
  • Arguments : objects are passed by reference to the object ("pass by assignment"): mutating a list argument changes the caller's list, but rebinding the name does not.
Decorators

A decorator is a function that takes a function and returns a replacement, applied with @.

import functools, time def timed(func): @functools.wraps(func) # keep the original name and docstring def wrapper(*args, **kwargs): start = time.perf_counter() try: return func(*args, **kwargs) finally: print(f"{func.__name__} took {time.perf_counter() - start:.3f}s") return wrapper @timed def slow(): time.sleep(1) @functools.cache # memoize results def fib(n): return n if n < 2 else fib(n - 1) + fib(n - 2)

Classes & OOP

class Account: bank = "PyBank" # class attribute, shared def __init__(self, owner: str, balance: float = 0): self.owner = owner # instance attribute self._balance = balance # "_" = internal by convention @property def balance(self): # read like an attribute: acct.balance return self._balance def deposit(self, amount): if amount <= 0: raise ValueError("amount must be positive") self._balance += amount @classmethod def empty(cls, owner): return cls(owner) @staticmethod def fee(amount): return amount * 0.01 def __repr__(self): return f"Account({self.owner!r}, {self._balance})" def __eq__(self, other): return isinstance(other, Account) and self.owner == other.owner class Savings(Account): def __init__(self, owner, rate): super().__init__(owner) self.rate = rate
  • No Private Members : _name means internal by convention; __name is name-mangled to _Class__name to avoid clashes, not for security.
  • Dunder Methods : special methods hook into the language: __len__, __getitem__, __iter__, __contains__, __add__, __enter__/__exit__, __hash__, __call__.
  • MRO : with multiple inheritance, methods are resolved in the C3 method resolution order (Class.__mro__); super() follows it.
  • Abstract Classes : abc.ABC with @abstractmethod. Protocols (typing.Protocol) describe interfaces structurally (duck typing).

Modules & Packages

import math from pathlib import Path from collections import Counter as C from .models import User # relative import inside a package if __name__ == "__main__": # true only when the file is run directly, not imported main()
  • Module : any .py file. Package : a directory of modules, usually with an __init__.py.
  • Search Path : imports are resolved through sys.path: the script's directory, PYTHONPATH, then installed packages (site-packages).
  • Caching : a module runs once per process and is cached in sys.modules.
  • Shadowing : a local file named like a standard module (e.g. random.py) is imported instead of it.

Exceptions

class InsufficientFunds(Exception): pass try: value = int(text) except ValueError as e: print("not a number:", e) except (KeyError, IndexError): pass else: print("ran only if no exception") finally: print("always runs") raise InsufficientFunds("balance too low") from original_error # chain exceptions try: ... except* ValueError as group: ... # handle exception groups (3.11+, e.g. from TaskGroup)
  • Hierarchy : all errors derive from Exception (under BaseException, which also covers KeyboardInterrupt and SystemExit); catch specific exceptions, never a bare except:.
  • EAFP : Pythonic code tries the operation and handles the exception ("easier to ask forgiveness than permission") rather than checking first.
  • Common Errors : TypeError, ValueError, KeyError, IndexError, AttributeError, FileNotFoundError, ImportError.

Concurrency & Async

Approach Best For
asyncio many concurrent I/O operations in one thread (network clients, servers)
threading / ThreadPoolExecutor blocking I/O with libraries that are not async
multiprocessing / ProcessPoolExecutor CPU-bound work, bypassing the GIL with separate processes
import asyncio async def fetch(session, url): async with session.get(url) as resp: # e.g. aiohttp or httpx.AsyncClient return await resp.text() async def main(urls): async with asyncio.TaskGroup() as tg: # 3.11+: cancels the rest if one fails tasks = [tg.create_task(fetch(session, u)) for u in urls] return [t.result() for t in tasks] asyncio.run(main(urls))

Never call blocking functions such as time.sleep or requests.get inside a coroutine; use await asyncio.sleep(), an async library, or asyncio.to_thread().

Best Practices & Security

  • Style : follow PEP 8 (4-space indentation, snake_case functions, PascalCase classes, UPPER_CASE constants) and format with Ruff or Black.
  • Environments : one virtual environment per project, with pinned dependencies (lock files).
  • Code Injection : never pass untrusted input to eval, exec, or pickle.loads (unpickling can run arbitrary code); use JSON for untrusted data and yaml.safe_load for YAML.
  • Commands : call subprocess.run(["ls", path]) with a list and without shell=True to avoid shell injection.
  • SQL : use parameterized queries: cur.execute("SELECT * FROM users WHERE id = ?", (uid,)).
  • Secrets : use the secrets module for tokens, not random; load credentials from environment variables, not source code.
  • Dependencies : scan with pip-audit and watch for typosquatted package names.
