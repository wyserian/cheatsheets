PHP

PHP (PHP: Hypertext Preprocessor) is a dynamically typed, server-side scripting language created by Rasmus Lerdorf in 1994. It powers a large share of the web, including WordPress, and frameworks such as Laravel and Symfony.

  • Zend Engine : the interpreter compiles scripts to opcodes and executes them. OPcache keeps compiled opcodes in shared memory, and PHP 8 adds an optional JIT compiler.
  • Request Model : traditionally share-nothing: each HTTP request starts with fresh state, and memory is freed when the request ends.
  • Runtimes : PHP-FPM (FastCGI process manager behind Nginx or Apache), mod_php (Apache module), the CLI, and long-running servers such as FrankenPHP, RoadRunner, and Swoole.
  • Versions : PHP 7 (2015) roughly doubled performance; PHP 8 (2020) added JIT, union types, attributes, and match. A new 8.x ships every November with two years of active support and two of security fixes.

Setup & Running

php -v # version php script.php # run a script from the command line php -a # interactive shell php -S localhost:8000 -t public # built-in development server (never in production) php -m # loaded extensions php --ini # which php.ini files are loaded php -l file.php # syntax check
<?php declare(strict_types=1); // per file: no silent scalar type conversion echo "Hello, World!", PHP_EOL;

  • php.ini : runtime settings such as memory_limit, max_execution_time, upload_max_filesize, display_errors, and error_reporting.

Arrays

PHP arrays are ordered hash maps: the same type serves as a list, a dictionary, a stack, and a queue. Keys are integers or strings.

  • Arguments : scalars and arrays are passed by value (arrays are copied on write); objects are passed as handles, so methods can change the same object.
  • Scope : functions do not see global variables unless passed in (or declared with global, which is best avoided).

Classes & OOP

<?php declare(strict_types=1); namespace App\Models; interface HasLabel { public function label(): string; } abstract class Model { abstract public function table(): string; } trait Timestamps { // reusable methods mixed into classes public ?\DateTimeImmutable $createdAt = null; public function touch(): void { $this->createdAt = new \DateTimeImmutable(); } } final class User extends Model implements HasLabel { use Timestamps; public const ROLE_ADMIN = 'admin'; private static int $count = 0; public function __construct( // constructor property promotion (8.0) public readonly int $id, // readonly (8.1): set once private string $name, protected array $roles = [], ) { self::$count++; } public function table(): string { return 'users'; } public function label(): string { return ucfirst($this->name); } public static function count(): int { return static::$count; } public function __toString(): string { return $this->label(); } } $user = new User(1, 'ada'); echo $user->label(), User::ROLE_ADMIN, User::count(); $user instanceof HasLabel; // true
  • Visibility : public, protected (class and subclasses), private (this class only).

  • Single Inheritance : a class extends one parent, implements many interfaces, and uses many traits.

Namespaces, Autoloading & Composer

  • Namespaces : group classes and avoid name clashes: namespace App\Http;, then use App\Models\User; or use Foo\Bar as Baz;.
  • PSR-4 Autoloading : maps a namespace prefix to a directory, so App\Models\User loads src/Models/User.php on first use without require.
  • Composer : the dependency manager; packages come from Packagist. composer.lock pins exact versions and should be committed.
  • PSR Standards : PHP-FIG recommendations such as PSR-1/PSR-12 (coding style), PSR-3 (logger), PSR-4 (autoloading), PSR-7 (HTTP messages), PSR-11 (container), and PSR-15 (middleware).
composer init # create composer.json composer require guzzlehttp/guzzle # add a dependency composer require --dev phpunit/phpunit composer install # install exactly what composer.lock says composer install --no-dev --optimize-autoloader # production composer update vendor/package # upgrade within version constraints composer dump-autoload composer audit # check for known vulnerabilities

Errors & Exceptions

class PaymentException extends RuntimeException {} try { $result = charge($order); } catch (PaymentException | InvalidArgumentException $e) { error_log($e->getMessage()); throw new RuntimeException('Checkout failed', previous: $e); } catch (Throwable $e) { // catches both Exception and Error report($e); } finally { $lock->release(); }
  • Hierarchy : Throwable has two branches: Exception (application errors, e.g. RuntimeException, InvalidArgumentException) and Error (engine errors, e.g. TypeError, ValueError, DivisionByZeroError).
  • Warnings & Notices : older functions emit warnings instead of throwing; convert them with set_error_handler or check return values (many return false on failure).
  • Production : set display_errors=Off and log_errors=On so stack traces are never shown to users.

Security Checklist

  • SQL Injection : always use prepared statements; never concatenate request values into SQL.
  • XSS : escape output for its context: htmlspecialchars($s, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8') for HTML, or use a template engine that escapes automatically (Blade, Twig).
  • Passwords : password_hash($pw, PASSWORD_DEFAULT) (bcrypt, or Argon2id with PASSWORD_ARGON2ID) and password_verify(); never md5 or sha1.
  • CSRF : add a random per-session token (bin2hex(random_bytes(32))) to forms and compare with hash_equals(); set SameSite cookies.
  • File Inclusion : never pass user input to include or require; keep allow_url_include=Off.
  • Command Injection : avoid exec, system, shell_exec, and backticks; if needed, wrap each argument in escapeshellarg().
  • Deserialization : never call unserialize() on untrusted data (it can trigger magic methods, "object injection"); use json_decode.
  • Type Juggling : use ===, hash_equals() for secrets, and in_array(..., true); loose comparison has enabled authentication bypasses.
  • Randomness : use random_bytes() and random_int(), not rand() or mt_rand(), for tokens.
  • Configuration : serve only the public/ directory, hide errors and expose_php in production, and keep PHP on a supported version.
