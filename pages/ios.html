iOS Overview

iOS is Apple's mobile operating system for the iPhone, first released in 2007 as iPhone OS. It is built on Darwin, the same Unix-based core as macOS, with the XNU kernel. Unlike Android, iOS is closed source (only parts of Darwin are open), runs only on Apple hardware, and Apple controls both the OS and the main app distribution channel.

  • Related Platforms : iPadOS (split from iOS in 2019), watchOS, tvOS, and visionOS share most frameworks and tooling.
  • Languages : Swift (since 2014, the primary language) and Objective-C (legacy, still used in older code and system frameworks); C and C++ for low-level code.
  • Distribution : mainly through the App Store, after Apple's App Review. In the EU, the Digital Markets Act also allows alternative app marketplaces (iOS 17.4) and direct web distribution (iOS 17.5), with Apple notarization.
  • Updates : Apple ships OS updates directly to all supported devices at once, so most users run a recent version.

iOS Versions

Apps declare a deployment target (the oldest iOS version they support) and are built with the latest SDK. Since 2025, iOS versions are numbered by year (iOS 26 follows iOS 18).

Version Year Key Changes for Developers
iOS 13 2019 SwiftUI, Combine, dark mode, Sign in with Apple, multiple scenes (windows) on iPad
iOS 14 2020 Home Screen widgets, App Clips, approximate location, limited photo access, App Tracking Transparency (enforced from 14.5)
iOS 15 2021 Swift concurrency (async/await), Focus modes, App Privacy Report
iOS 16 2022 Lock Screen widgets, passkeys, Lockdown Mode, Live Activities (16.1)
iOS 17 2023 Observation (@Observable), SwiftData, interactive widgets, privacy manifests, alternative distribution in the EU (17.4)
iOS 18 2024 Apple Intelligence, locked and hidden apps, limited contacts access, Control Center controls
iOS 26 2025 Liquid Glass design, the Foundation Models framework (on-device language model for apps), new year-based numbering
  • App Store Requirement : new submissions must be built with a recent Xcode and iOS SDK, which Apple updates each spring.
  • Availability Checks : guard newer APIs with if #available(iOS 17, *) { ... } or mark code with @available(iOS 17, *).

App Development & IPA

Languages & Tooling
  • Xcode : the official IDE, available only on macOS; includes the compiler, Interface Builder, Simulator, Instruments, and signing tools.
  • Swift Package Manager : the built-in dependency manager. CocoaPods (now in maintenance mode) and Carthage are older alternatives.
  • SwiftUI vs UIKit : SwiftUI is the modern declarative UI framework; UIKit is the mature imperative one. They can be mixed in one app (see App Architecture).
  • Simulator : runs iOS apps natively on the Mac (it is not an emulator), so some hardware features and performance differ from a real device.
Project Structure
  • .xcodeproj / .xcworkspace : project settings, targets, and build configurations.
  • Info.plist : app metadata and configuration (bundle ID, version, permissions text); see Info.plist & Permissions.
  • .entitlements : capabilities the app is allowed to use (push, iCloud, App Groups, Associated Domains).
  • Assets.xcassets : images, app icons, and colors in light and dark variants.
  • Localizable.xcstrings : String Catalog with translated user-facing text (Xcode 15+), replacing .strings files.
  • Targets : the app plus extensions (widgets, share, notification service), unit tests, and UI tests.
Build Process
Swift / Objective-C --(swiftc / clang, LLVM)--> Mach-O executable (arm64) Assets.xcassets --(actool)--> Assets.car Storyboards / XIBs --(ibtool)--> compiled .storyboardc / .nib --> MyApp.app bundle --(codesign)--> signed .app --(zip Payload/)--> .ipa
IPA Structure

An IPA is a ZIP archive containing the app bundle:

  • Payload/MyApp.app/MyApp : the compiled Mach-O executable.
  • Info.plist : compiled app metadata.
  • _CodeSignature/CodeResources : hashes of every file, covered by the code signature.
  • embedded.mobileprovision : the provisioning profile (development and ad hoc builds).
  • Frameworks/ : embedded dynamic frameworks. PlugIns/ : app extensions.
  • Assets.car, *.lproj/ : compiled assets and localizations. PrivacyInfo.xcprivacy : the privacy manifest.
Code Signing & Provisioning
  • Apple Developer Program : required to distribute apps (US $99 per year).
  • Certificates : a development certificate signs builds for testing; a distribution certificate signs App Store and ad hoc builds.
  • App ID / Bundle ID : the unique identifier, e.g. com.example.app, prefixed by the team ID.
  • Provisioning Profile : ties together the App ID, certificate, entitlements, and (for development and ad hoc) the allowed device list. iOS refuses to run an app whose signature or profile does not match.
  • Automatic Signing : Xcode can create and renew certificates and profiles for you.

Reverse-Engineering Tools

Used for debugging, security review, and malware analysis, only on apps you are authorized to inspect. App Store binaries are encrypted with FairPlay DRM.

  • otool / nm : inspect Mach-O headers, linked libraries, and symbols.
  • class-dump : list Objective-C classes and methods.
  • Ghidra / Hopper : disassemble and decompile binaries.
  • Frida / objection : dynamic instrumentation for runtime analysis.

System Architecture

iOS is organized in layers. Apps mostly use the top layers, which are built on the lower ones.

Cocoa Touch / App Frameworks UIKit, SwiftUI, UserNotifications, MapKit, WidgetKit Media Core Graphics, Core Animation, Metal, AVFoundation, Core Audio Core Services Foundation, Core Data, CloudKit, Core Location, networking Core OS XNU kernel (Mach + BSD), IOKit drivers, Security, Keychain Hardware Apple silicon, Secure Enclave
Core Components
  • XNU Kernel : a hybrid kernel combining the Mach microkernel (tasks, threads, virtual memory, IPC), BSD (processes, users, file systems, networking, POSIX APIs), and IOKit (an object-oriented driver framework).
  • launchd : the first user-space process (PID 1); starts and supervises all system daemons and apps.
  • SpringBoard : the Home Screen and app launcher.
  • dyld : the dynamic linker. System frameworks are pre-linked into one large dyld shared cache for faster launches.
  • Mach-O : the executable file format (the equivalent of ELF on Linux).
  • XPC : lightweight IPC used to split system services and app extensions into separate, sandboxed processes.
  • Runtimes : the Objective-C runtime (dynamic message dispatch) and the Swift runtime; there is no virtual machine, since apps compile ahead of time to native ARM code.

App Lifecycle & Components

iOS has no direct equivalent of Android's four app components. Apps are built from scenes, view controllers or SwiftUI views, and separate app extensions, and the system tightly limits what runs in the background.

App States
State Meaning
Not running not launched, or terminated by the system

  • UIKit Lifecycle : UIApplicationDelegate handles app launch (application(_:didFinishLaunchingWithOptions:)); UISceneDelegate handles each window (sceneDidBecomeActive, sceneWillResignActive, sceneDidEnterBackground).
  • App Extensions : widgets, share, action, notification service and content, keyboard, Safari, and intents extensions each run as a separate process with their own limits.
  • App Clips : small parts of an app (under a size limit) that launch instantly from a link, NFC tag, or QR code without a full install.
Background Execution
Need Use
finish a task after leaving the screen beginBackgroundTask (a short, system-decided amount of time)
periodic content refresh BGAppRefreshTask via BGTaskScheduler (the system decides when)
long maintenance work (sync, ML) BGProcessingTask, often only while charging

  • Jetsam : the system terminates background apps under memory pressure, so save state when entering the background.
  • Watchdog : an app that takes too long to launch or blocks the main thread is terminated (crash reports show the exception code 0x8badf00d).
  • Main Thread : all UI work must run on the main thread; Swift concurrency marks it with @MainActor.

Info.plist & Permissions

Info.plist describes the app to the system, while the entitlements file, signed into the app, grants access to protected capabilities. Together they play the role of Android's manifest.

Common Info.plist Keys
Key Purpose
CFBundleIdentifier bundle ID, e.g. com.example.app
CFBundleShortVersionString / CFBundleVersion user-facing version (1.4.0) / build number (must increase)
NS…UsageDescription text shown in permission prompts (required; the app crashes if missing)
CFBundleURLTypes custom URL schemes the app handles
LSApplicationQueriesSchemes other apps' schemes the app may check with canOpenURL
UIBackgroundModes allowed background work (audio, location, remote notifications)
NSAppTransportSecurity network security exceptions and certificate pinning
<key>NSCameraUsageDescription</key> <string>Scan receipts to add expenses automatically.</string> <key>NSLocationWhenInUseUsageDescription</key> <string>Show stores near you.</string> <key>NSUserTrackingUsageDescription</key> <string>Allow personalized ads across other apps and websites.</string>
Permissions
  • TCC (Transparency, Consent, and Control) : the system service that shows permission prompts and stores the user's decisions.
  • One Prompt : the system asks only once. After a denial, only the user can change it in Settings, so request permissions in context and explain the benefit first.
  • Authorization States : notDetermined, authorized, denied, restricted (blocked by parental controls or MDM), and limited (selected photos or contacts only).
  • Location : when-in-use or always, and precise or approximate.
  • App Tracking Transparency (ATT) : apps must ask before tracking users across other companies' apps and websites; if the user declines, the advertising identifier (IDFA) returns all zeros.
  • Avoid Permissions : PHPickerViewController / SwiftUI PhotosPicker give access to chosen photos without any permission.
switch AVCaptureDevice.authorizationStatus(for: .video) { case .authorized: openCamera() case .notDetermined: AVCaptureDevice.requestAccess(for: .video) { granted in DispatchQueue.main.async { granted ? openCamera() : showSettingsHint() } } default: showSettingsHint() // denied or restricted: only the user can change it in Settings }
Entitlements & Capabilities
  • Examples : Push Notifications (aps-environment), App Groups, Keychain Sharing, Associated Domains, iCloud, HealthKit, Sign in with Apple.
  • Enforcement : entitlements are enabled in Xcode, approved for the App ID, embedded in the provisioning profile, and covered by the code signature, so an app cannot grant itself new capabilities.
Privacy Manifest
  • PrivacyInfo.xcprivacy : declares the data the app and its SDKs collect, whether it is used for tracking, and the tracking domains.
  • Required-Reason APIs : APIs that could be used for fingerprinting (e.g. UserDefaults, file timestamps, system boot time, disk space) need a declared, approved reason. Required for App Store submissions since May 2024.
  • Third-Party SDKs : commonly used SDKs must include their own privacy manifest and signature.

URL Schemes & Universal Links

Deep links open a specific screen inside an app. iOS supports two mechanisms:

Type Example Behavior
Custom URL scheme myapp://product/42 declared in CFBundleURLTypes; not unique, so any app can claim the same scheme
Universal Link https://example.com/product/42 verified through the website, opens the app directly, and falls back to the website if the app is not installed
Deferred deep link a link opened before the app is installed no built-in support; done through App Store attribution or a third-party service
Setting Up Universal Links
  • Associated Domains Entitlement : add applinks:example.com in Xcode (Signing & Capabilities).
  • AASA File : the website serves https://example.com/.well-known/apple-app-site-association as JSON over HTTPS, with no redirects and no .json extension. Since iOS 14, devices fetch it through Apple's CDN, not directly from your server.
  • Development Mode : applinks:example.com?mode=developer fetches the file directly from your server, bypassing the CDN cache, on devices with developer mode enabled.
{ "applinks": { "details": [ { "appIDs": ["ABCDE12345.com.example.app"], "components": [ { "/": "/product/*", "comment": "open product pages in the app" }, { "/": "/account/*", "exclude": true } ] } ] }, "webcredentials": { "apps": ["ABCDE12345.com.example.app"] } }
Handling Links
// SwiftUI: receives both custom-scheme URLs and Universal Links ContentView() .onOpenURL { url in guard url.pathComponents.count >= 3, url.pathComponents[1] == "product", let id = Int(url.pathComponents[2]) else { return } // validate before use router.showProduct(id) } // UIKit (scene delegate) func scene(_ scene: UIScene, continue userActivity: NSUserActivity) { // Universal Links guard userActivity.activityType == NSUserActivityTypeBrowsingWeb, let url = userActivity.webpageURL else { return } handle(url) } func scene(_ scene: UIScene, openURLContexts contexts: Set<UIOpenURLContext>) { // custom schemes contexts.first.map { handle($0.url) } }
  • Cold Launch : if the app was not running, UIKit delivers the link in scene(_:willConnectTo:options:) through connectionOptions.userActivities / connectionOptions.urlContexts, not the methods above; SwiftUI's .onOpenURL handles both cases.
  • When Universal Links Do Not Open the App : when the URL is typed into Safari, when navigating within the same domain, or after the user long-presses and chooses to open in Safari.
  • Testing : xcrun simctl openurl booted "https://example.com/product/42", or tap the link in Notes or Messages on a device.
Security
  • Scheme Hijacking : another app can register the same custom scheme, so never put tokens or secrets in custom-scheme links; use Universal Links for anything sensitive.
  • Untrusted Input : validate every path component and query parameter.
  • No Silent Actions : a link should only navigate; require confirmation and authentication for payments or account changes.
  • OAuth : use ASWebAuthenticationSession (the system browser sheet) with PKCE, rather than an embedded web view.

Notifications & Push

  • Authorization : request permission with UNUserNotificationCenter. Provisional authorization delivers notifications quietly to Notification Center without a prompt, so users can decide later.
  • APNs (Apple Push Notification service) : the app registers and receives a device token; your server sends notifications to APNs over HTTP/2, authenticated with a token-based key (.p8, signed JWT) or a certificate.
  • Payload Limit : 4 KB (5 KB for VoIP pushes).
  • Interruption Levels : passive, active (default), time-sensitive (breaks through Focus), and critical (bypasses mute; needs a special entitlement).
  • Silent Pushes : "content-available": 1 wakes the app in the background to fetch data; the system throttles them and may not deliver every one.
  • Notification Service Extension : modifies a notification before it is shown, e.g. to decrypt an end-to-end encrypted message or attach an image.
  • Live Activities : live-updating content on the Lock Screen and Dynamic Island (ActivityKit), updated locally or through APNs.
let center = UNUserNotificationCenter.current() let granted = try await center.requestAuthorization(options: [.alert, .sound, .badge]) if granted { await MainActor.run { UIApplication.shared.registerForRemoteNotifications() } } // The device token arrives in application(_:didRegisterForRemoteNotificationsWithDeviceToken:)
{ "aps": { "alert": { "title": "Order shipped", "body": "Your order #1042 is on the way" }, "sound": "default", "badge": 1, "thread-id": "orders" }, "orderId": "1042" }

Security : treat push payloads as untrusted and fetch sensitive data from your server after the notification arrives, rather than including it in the payload.

App Architecture & Frameworks

UI Frameworks
  • SwiftUI : declarative; views are structs whose body is recomputed when state changes. Property wrappers manage state: @State (owned by the view), @Binding (a reference to a parent's state), @Environment (shared values), and @Observable classes (iOS 17) for models.
  • UIKit : imperative; UIViewControllers manage views laid out with Auto Layout, in storyboards, XIBs, or code. UITableView / UICollectionView display lists and grids.
  • Interoperability : UIHostingController embeds SwiftUI in UIKit; UIViewRepresentable embeds UIKit views in SwiftUI.
import SwiftUI @Observable final class CounterModel { var count = 0 } struct CounterView: View { @State private var model = CounterModel() let name: String var body: some View { VStack(spacing: 12) { Text("Hello, \(name)") Button("Clicked \(model.count) times") { model.count += 1 } } .padding() } }
Architecture Patterns
  • MVC : Apple's traditional pattern for UIKit; prone to "massive view controllers" when logic piles up.
  • MVVM : views observe a view model that holds state and logic; a natural fit for SwiftUI.
  • The Composable Architecture (TCA) : unidirectional state, actions, and reducers, popular in larger SwiftUI apps.
  • VIPER / Clean Architecture : stricter layering for large teams.
Swift Concurrency
  • async / await : asynchronous code that reads like synchronous code.
  • Task : starts asynchronous work; tasks form a tree, so cancelling a parent cancels its children (structured concurrency).
  • Actors : protect mutable state from data races by allowing one task at a time; @MainActor runs code on the main thread.
  • Sendable : marks types that are safe to share between concurrent tasks; Swift 6 checks data-race safety at compile time.
@MainActor @Observable final class ProfileViewModel { var user: User? private let api: APIClient init(api: APIClient) { self.api = api } func load(id: Int) async { do { user = try await api.user(id: id) } // awaiting does not block the main thread catch { user = nil } } }

Networking & App Transport Security

  • URLSession : the built-in HTTP client, with async/await support, background transfers that continue after the app is suspended, and HTTP/2 and HTTP/3.
  • Codable : converts JSON to and from Swift types with JSONDecoder / JSONEncoder.
  • Network Framework : low-level TCP, UDP, and QUIC connections (NWConnection), and NWPathMonitor to detect connectivity changes.
  • Alamofire : a popular third-party wrapper around URLSession.
struct User: Decodable { let id: Int let name: String } func fetchUser(id: Int) async throws -> User { let url = URL(string: "https://api.example.com/users/\(id)")! let (data, response) = try await URLSession.shared.data(from: url) guard (response as? HTTPURLResponse)?.statusCode == 200 else { throw URLError(.badServerResponse) } return try JSONDecoder().decode(User.self, from: data) }
App Transport Security (ATS)
  • Default : since iOS 9, apps may only connect over HTTPS using TLS 1.2 or later with forward secrecy.
  • Exceptions : configured per domain under NSAppTransportSecurity; App Review asks for a justification, and NSAllowsArbitraryLoads (disabling ATS entirely) is a red flag in audits.
  • Certificate Pinning : NSPinnedDomains (iOS 14+) pins public keys declaratively, without code. Include a backup key so a key rotation does not lock users out.
<key>NSAppTransportSecurity</key> <dict> <key>NSPinnedDomains</key> <dict> <key>api.example.com</key> <dict> <key>NSIncludesSubdomains</key> <true/> <key>NSPinnedLeafIdentities</key> <array> <dict> <key>SPKI-SHA256-BASE64</key> <string>r/mIkG3eEpVdm+u/ko/cwxzOMo1bk4TyHIlByibiA5E=</string> </dict> <dict> <key>SPKI-SHA256-BASE64</key> <string>YLh1dUR9y6Kja30RrAn7JKnbQG/uEtLMkBgFF2Fuihg=</string> <!-- backup key --> </dict> </array> </dict> </dict> </dict>

The pin values above are placeholders; real pins are the Base64 SHA-256 hash of the server's public key (SPKI).

Data Storage & Keychain

Each app runs in a sandbox with its own containers, identified by a random UUID that changes when the app is reinstalled.

Location Contents Backed Up
Bundle container (MyApp.app) the signed app itself; read-only no
Documents/ user-created data; can be shown in the Files app yes
Library/Application Support/ app-managed files and databases yes
Library/Caches/ re-creatable data; the system may delete it when space is low no
Library/Preferences/ UserDefaults property list files yes
tmp/ temporary files, cleared by the system no
App Group container data shared between your app and its extensions yes
Storage Options
  • UserDefaults : small key-value preferences stored in a plist file; not for secrets.
  • Files : read and written with FileManager in the containers above.
  • SwiftData / Core Data : object persistence on top of SQLite; SwiftData (iOS 17) is the Swift-native API.
  • SQLite : directly or through libraries such as GRDB.
  • CloudKit / iCloud : sync data across a user's devices.
Keychain

The Keychain is the encrypted system store for passwords, tokens, and keys. Items are encrypted with keys protected by the Secure Enclave, and they remain after the app is deleted, so clear them on first launch if that matters.

Accessibility Available
kSecAttrAccessibleWhenUnlocked only while the device is unlocked (default)
kSecAttrAccessibleAfterFirstUnlock after the first unlock since boot, also in the background
kSecAttrAccessibleWhenPasscodeSetThisDeviceOnly only if a passcode is set; deleted if the passcode is removed
…ThisDeviceOnly variants never migrated to another device through backups
import Security func saveToken(_ token: String) -> Bool { let base: [String: Any] = [ kSecClass as String: kSecClassGenericPassword, kSecAttrService as String: "com.example.app", kSecAttrAccount as String: "authToken" ] SecItemDelete(base as CFDictionary) // remove any old value var item = base item[kSecValueData as String] = Data(token.utf8) item[kSecAttrAccessible as String] = kSecAttrAccessibleWhenUnlockedThisDeviceOnly return SecItemAdd(item as CFDictionary, nil) == errSecSuccess }
  • Biometric Protection : an item can require Face ID or Touch ID on every read using SecAccessControl with .biometryCurrentSet (invalidated if biometrics change).
  • Secure Enclave Keys : P-256 private keys can be generated inside the Secure Enclave (CryptoKit's SecureEnclave.P256); they can be used for signing but never exported.
Data Protection Classes
Class File Accessible
.complete only while the device is unlocked
.completeUnlessOpen files already open stay accessible after locking
.completeUntilFirstUserAuthentication after the first unlock since boot (default for apps)
.none always (protected only by the device UID key)

Each file has its own key, wrapped by a class key derived from the user's passcode and the device's hardware UID key, so data cannot be decrypted off the device.

App Security Checklist

The OWASP MASVS applies to iOS as well: MASVS-STORAGE, CRYPTO, AUTH, NETWORK, PLATFORM, CODE, RESILIENCE, and PRIVACY, with iOS-specific tests in the MASTG.

  • No Secrets in the Binary : API keys in code or plist files can be extracted; keep them on a server, and store user tokens in the Keychain.
  • Keychain Settings : use the strictest accessibility class that works, prefer ThisDeviceOnly for tokens, and add biometric protection for high-value items.
  • File Protection : use .complete protection for sensitive files.
  • Network : keep ATS on, avoid NSAllowsArbitraryLoads, and pin keys for high-risk apps.
  • Links : validate every URL-scheme and Universal Link parameter.
  • Web Views : use WKWebView (apps using the deprecated UIWebView are rejected), keep JavaScript bridges (WKScriptMessageHandler) away from untrusted content, and load only HTTPS pages you control.
  • Logging : never log tokens or personal data, and keep the default private redaction.
  • App Switcher Snapshot : iOS saves a screenshot of the app when it goes to the background; hide sensitive screens before that happens.
  • Pasteboard : sensitive data copied to the general pasteboard is visible to other apps; use local, expiring pasteboard items.
  • Secure Text Fields : isSecureTextEntry fields disable third-party keyboards and hide their content from screen recordings and AirPlay.
  • Integrity : verify App Attest assertions on your server; client-side jailbreak detection is only a signal and can be bypassed.
  • Privacy : keep the privacy manifest accurate and request ATT only when the app really tracks.
Review Tools (for your own apps)
  • Xcode Static Analyzer : Product > Analyze.
  • MobSF : automated static and dynamic analysis of IPA files.
  • otool / class-dump : check what a release build exposes (see App Development & IPA).

File System

  • APFS : the Apple File System, used since iOS 10.3, with copy-on-write, snapshots, and native per-file encryption.
  • Read-Only System : the system volume is mounted read-only and verified, so the OS cannot be modified at runtime.
  • No Shared File System : apps cannot browse each other's files; sharing happens through the share sheet, the Files app, File Provider extensions, or App Groups.
Path Contents
/System the operating system, frameworks, and system apps (read-only)
/private/var/containers/Bundle/Application/<UUID>/ installed app bundles
/private/var/mobile/Containers/Data/Application/<UUID>/ each app's data container (Documents, Library, tmp)
/private/var/mobile/Containers/Shared/AppGroup/<UUID>/ App Group shared containers
/private/var/mobile/Media/ photos (DCIM) and media
/var a symbolic link to /private/var

Apps should never hard-code these paths; use FileManager APIs such as urls(for: .documentDirectory, in: .userDomainMask).

Boot Process

Boot ROM (immutable, contains Apple's root public key) -> iBoot (bootloader, verified by the Boot ROM) -> XNU kernelcache (kernel + drivers, verified by iBoot) -> launchd (PID 1) -> system daemons -> SpringBoard
  • Secure Boot Chain : each stage verifies the cryptographic signature of the next before running it, so only Apple-signed software boots.
  • Personalized Signing : Apple's signing server signs each OS installation for a specific device (identified by its ECID). Older iOS versions stop being signed, which prevents downgrading to versions with known vulnerabilities.
  • Secure Enclave Boot : the Secure Enclave runs its own separately verified OS (sepOS).
  • Recovery Mode : iBoot-level mode for restoring or updating through a computer.
  • DFU (Device Firmware Update) Mode : the lowest-level restore mode, handled directly by the Boot ROM; used when the bootloader itself is damaged.

iOS Security Core

  • Secure Enclave : a separate coprocessor with its own memory and boot process. It holds the keys for Data Protection, Keychain, and Apple Pay, and processes Face ID and Touch ID data, which never leaves it.
  • Code Signing Enforcement : every executable page must be signed by Apple or an Apple-issued developer certificate; apps cannot download and run new native code, and JIT compilation is restricted to approved cases.
  • App Sandbox : every app runs in its own container with a sandbox profile (Seatbelt) limiting files, system services, and hardware access to what its entitlements allow.
  • Data Protection : per-file encryption tied to the passcode and the hardware UID key (see Data Storage).
  • Exploit Mitigations : ASLR, non-executable memory, Pointer Authentication Codes (PAC, from A12 chips) that sign pointers to block code-reuse attacks, kernel integrity protection, and Memory Integrity Enforcement (hardware memory tagging, from A19 chips).
  • BlastDoor : parses untrusted iMessage content in a tightly sandboxed process.
  • Lockdown Mode : an optional extreme-protection mode for people at risk of targeted attacks, disabling complex features such as many message attachments and web technologies.
  • Stolen Device Protection : requires Face ID or Touch ID, and a time delay away from familiar locations, for sensitive changes like the Apple Account password.
  • Inactivity Reboot : a device left locked for several days restarts, returning to the stronger "before first unlock" state where most data keys are unavailable.
  • USB Restricted Mode : USB accessories cannot exchange data with a device that has been locked for over an hour until it is unlocked.

Apple Ecosystem

  • App Store Connect : app listings, builds, App Review submission, TestFlight, phased releases, analytics, and crash reports.
  • App Attest (DeviceCheck) : generates a key in the Secure Enclave and an attestation from Apple, letting your server verify requests come from a genuine instance of your app on a real Apple device. Verify it on the server.
  • Sign in with Apple : privacy-focused login with an optional private relay email. Apps that offer third-party social logins must also offer an equivalent privacy-focused option, which Sign in with Apple satisfies.
  • iCloud / CloudKit : per-user storage and database sync across devices.
  • StoreKit & App Store Server API : in-app purchases and subscriptions, with server-side verification of signed transactions.
  • Apple Pay (PassKit) : tokenized card payments and Wallet passes.
  • MDM & Apple Business Manager : manage company devices, distribute custom apps, and enforce policies.

Jailbreak

Jailbreaking removes iOS's software restrictions to gain root access, run unsigned code, and modify the system. It is the iOS counterpart of Android rooting, but much harder: it requires chaining exploits for unpatched vulnerabilities, because the bootloader cannot be unlocked.

Types of Jailbreaks
Type After a Reboot
Untethered stays jailbroken on its own
Tethered needs a computer to boot at all
Semi-tethered boots normally but unjailbroken; a computer re-applies the jailbreak
Semi-untethered boots normally; an app on the device re-applies the jailbreak
  • Bootrom Exploits : flaws in the read-only Boot ROM cannot be patched by software updates, so they affect a hardware generation permanently (e.g. checkm8 in 2019, affecting A5 to A11 chips).
  • Rootless Jailbreaks : since the system volume became sealed and verified, modern jailbreaks install their files under /var/jb instead of modifying the system volume.
  • Tweaks & Package Managers : code-injection frameworks load modifications (tweaks) into apps and system processes; package managers such as Sileo distribute them.
  • Risks : the sandbox, code signing, and Data Protection guarantees no longer hold, malicious tweaks get full access, updates are blocked, and many banking and enterprise apps refuse to run.
  • For App Developers : treat jailbreak detection as one risk signal, not a security boundary; enforce sensitive checks on the server with App Attest.
